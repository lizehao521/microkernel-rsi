# 只带这本账换一个进程：能审计，供不出历史

日期：2026-10-13 · 驱动：`tasks/mcp/replay.py` · **一次端点都不打**（不花钱、不需要 key）
输入：`报告/样例-工具提议.jsonl`（235 条，工具提议那五发的账）+ `报告/工具提议.txt`（驱动自己的日志）
全程输出：`报告/续跑重建.txt` · 判定：**3 条、0 红**

问的是这一句：框架挂了，**只把这本账交给新进程，它能不能接着跑下一发**？
「能不能重启并验链」挂载第二轮就答过（能）；这一支问的是另一件事 —— 续跑要的是**内容**，
而账本记的是**关于内容的数**。

## 1. 读数

```
载入（新进程、空账本）：从 235 行里读回 235 条，链上现在 235 条；原像 235 条在手
✓ 链自洽（共 235 条，其中 235 条比对过原像）

每一发 output 侧 27 格都读得回来，其中装着「模型说了什么」的只有这四格：
  model_says_bytes=22   model_says_kept=22   model_says_clipped=否   model_says_sha256=182e3adb56a3…

(2) 逐发按同一规则重算指纹：对上 3 发、对不上 0 发、跳过 2 发（跳过的没有原文可比）
```

`e3b0c44298fc1c14…` 那两格对得上也是有意义的：那是空手两发的 `sha256("")` ——
「模型一个字没说」和「这一格没记」在账上从来不长一样（规矩一那一族），这里再确认一次。

**所以账本能审计**：谁手里有原文，就能证明它正是当时记下那一发。
**账本供不出历史**：下一发的 `messages` 一个字节都重建不出来。

## 2. 一支方法错误，值得单独记

第一版我拿「在整本账的文本里搜那句话」当证据，跑出来是：

```
拿 5 句原话在整本账里逐字找：找到 2 句 → ['\n', '4']
```

**看着像「账本确实存了原话」，其实是假命中**：那两"句"各只有 1 个字节。
任何 1 个字符的串都会在任何一本有数字格的账里撞上某一行（`4` 撞的是一个计数格）。
判据当场报红，红的正是我自己的搜索方法 —— 这一条如果不写下来，下一个人会以为账本存了文本。

改成两条一起看，并且**短句子不再拿来当证据**：

- **结构**：数一数「关于模型说了什么」的格有哪几个 —— 只有 `bytes / kept / clipped / sha256`，
  全是数与指纹；内核的 `Says` 结构体里压根没有文本字段（`output.go`）。
- **逐字**：只拿**长过 8 字节**的句子去和**每一格的 claim 精确比**（不是子串、不是整本文件）。
  本轮可靠样本只有 1 句（第 2 发那 22 字节），命中 0 格。
  **这一条的火力有多薄，就写在这里**：它靠的是「结构上无处可放」，不是「我搜了很多句都没搜到」。

```
(1b) 长过 8 字节的原话 1 句，与某一格 claim 完全相等的：[]；另有 2 句短到 8 字节以内，故意不拿来判
(1b) 反例：拿整本账做子串搜索会「找到」2 句 —— ['\n', '4'] —— 那是假命中，不是证据
```

还有一层要说清：账上**确实有两处自由文本** —— `fail_detail` 与 `notice_text`，
住的都是**我们自己写的句子**（上一支里我为了留住那个 401，就是把它写进 `fail_detail` 的散文里）。
别把这两处读成「原文有地方放，是我没填」。

## 3. 两张清单，不含糊成一句「不够」

**只带这本账能重建**：模型说了几句、每句话的指纹、收尾原因、自报模型名、
提议几个 / 几个歪 / 链上连歪几发、收发字节、帧数、首帧、最大帧间、token 自报数、
哪些段整段没带进下一发（`folded`/`clipped`/`dropped`，还带那一段的原文指纹）、
有没有故障、哪一类、要不要重发（`RetrySame` 由类别推）。

**只带这本账重建不出**：模型原话本身、人问过的题面原文、工具返回的正文原文（`observation` 只剩字节数）、
system 说明书原文、这一趟对话的内容。

架构结论一句话：**框架要续跑，原文必须自己另存；账本在旁边核它。**

## 4. 顺带：我自己的日志也不是恢复件

这一支的原文只能从 `报告/工具提议.txt` 里捞，因为驱动那份 `tools-raw.json` 被后面那轮假 key 实验
**同名覆盖了**（它固定写在 TEMP 的一个路径上）。而那份日志印原时限长 160 字节 ——
所以「拿日志重算指纹」这条路只对本轮那种短句子成立。
两处都是我自己的留痕方式不够，不是内核的事，但结论受影响时要如实说：
**可比样本 3 发，不是 5 发**。

## 5. 要不要新开一格「原文入库」，我不替用户定

 tempting 的做法是给 `Says` 加一个文本字段，账本从此能供历史。代价不止一行字段：

1. 模型的**每一句输出**从此进账，而账本是要落盘、要被别人读走的。
   `Failure.Detail` 那条脱敏契约（README 缺口 5）今天只管「我们自己写的句子」，
   一扩就变成管「模型说的一切」—— 而模型是完全可能把密钥复述出来的。
2. 46 个键名那张表今天是**一格一个数**；加一格不定长文本，
   「格位表」这一层第一次要装大小不可控的内容，`kcheck` 与审计脚本的分母口径都要跟着改。

所以这件事我只写到 **README 缺口 12** 与 **`contract.md` §2.3**（后者补了一句口径：
`payload_b64` 是**这一格自己的值**的原像，不是模型的原话；这本账是审计件，不是恢复件）。
定了之前，**`load_journal` 成功 ≠ 恢复了现场**。
