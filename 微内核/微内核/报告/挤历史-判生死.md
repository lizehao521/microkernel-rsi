# 挤历史那一发：判生死判出了两条我原先没预见的东西

日期：2026-10-13 · 端点：**本机假端点，全程 0 花钱** · 驱动：`tasks/mcp/tools_probe.py` 加 `FOLD=1` 旋钮

## 0. 两臂

| 臂 | 结果 |
|---|---|
| 对照（不设 `FOLD`） | `status=OK checks=20 red=0 turns=5` —— **我在驱动里加的折叠逻辑没碰坏在册那五发** |
| 折叠（`FOLD=1`） | `status=RED checks=23 red=9 turns=5`，账上 **141 条**（=3 发），**被拒的写入 2 次** |

## 1. 挤尾真的发生了一次，而且账记住了"挤过"这件事

第 2 发模型真回 `和是 42。`，装配第 3 发历史时留前缀、挤掉尾巴，发出去的是 `和是`；
`Cuts` 里落了一条 `tail-dropped`（`FromBytes`/`ToBytes`/段指纹都在），通知也真作为
`truncation-notice` 段发了出去（正文换成"只带了前缀进这一轮"那句）。

## 2. 第一个结论：三条指纹互不相同，所以**谁也连不回它是哪一句**

```
(12) 第 2 发原话 '和是 42。' 挤成 '和是'
    账上 model_says     = addd5ed1ab…   ← 原话整句的指纹（我另算了一遍，与它 ✓ 对得上 —— 账没错）
    裁剪表记的那条       = 002ee28b71…   ← 它记的是**段**：JSON 壳 + content，不是那句原话
    真发出去的那句的指纹  = da364b8d7f…   ← 账上没有一格记它
```

三把里没有两把是同一个量。所以 `#13` 那条"跨发比对"不是被我关掉了，而是被**定位**了：
账本身是对的（原话指纹能对上），缺的是**裁剪表的指纹单位与"原话"不是同一个单位**，
外加"发出去的那个前缀"根本没有格存它。这跟我原先猜的"缺一段比对代码"不一样 ——
**比对代码写不了，因为两边量的不是同一件事。**

## 3. 第二个结论（这条更要紧）：挤历史会**级联**，而内核把第二次挤拦下来了

第 3、4 发继续跑时，我的驱动**又去挤同一段** —— 而那段已经是上一轮挤剩的前缀，
`和是` 再切 6 个字节还是 `和是`。内核整发拒收，原话是：

```
kernel: 第 2 条裁剪记录（history/第 3 发模型那句回答（挤尾留前缀））
        留了 42 字节、原文 42 字节 —— 裁尾要留下一个非空的真前缀
```

这是本 session 内核**第四次当面纠正我**（前三次：200 空响应记成正常收尾、`protocol` 带 200、
新调用方把 usage 标成 measured）。它钉的是"你说是裁尾，那留下的必须真比原文短"。

而它顺带把一个我以前没想过的真问题摆到台面上：**账上没有一格说"这段已经挤过了"**。
`Cuts` 记的是"哪一发挤了什么"，不记"这段现在是第几手前缀"。
预算真紧起来时，同一段会被连着挤好几轮，每一轮都只能跟**上一轮**比 ——
读账的人看不出那段已经被挤过几次，也看不出它离原话隔了几手。
（第 3 发更极端：它记的原话是空串，指纹 `e3b0c44298…` 就是 `sha256("")`。）

## 5. `#13` 怎么判

**不关。** 它从"我造的零观测假问题"升级成"**有真实路径、有实测的两条缺口**"：
路径是真的（`MayShrink` 明确允许 `tail-dropped`，级联时内核也确实拦了），
实例是我逼出来的（预算没自然紧到那份上 —— 这句得留在账上，不许读成"生产里天天发生"）。

拆成两件事，归属不同，别混：

1. **调用方现在就能修，不动判据**：记住"这段挤过"，第二次不许再按 `tail-dropped` 记（要么整段丢弃 `dropped-whole`，要么不动）。
2. **要"连回原话"就得改判据表**：裁剪表那条指纹要么换成 content 级、要么新增一个可核引用（指向"第几发的哪一句"）。
   这跟 `fail_kind↔status`、`wire_format` 是**同一个文件、同一张表** → 并进第 2 步那一轮一起拍，别改三轮。

原始件：`报告/挤历史-真挤那趟.txt`、`报告/挤历史-对照没挤.txt`、`报告/样例-挤历史.jsonl`（141 条，`sk-` 0 次）。
复现：`FOLD=1` + 假端点；`FOLD_KEEP` 控制留几个字节。每臂记得重启假端点（它的全局 429 计数器会串臂）。

## 6. 修完再跑：真端点那一趟（用户指定"用 LLM 跑"）

先把调用方两处修了，再打真端点：

| 修的东西 | 怎么坏的 | 改法 |
|---|---|---|
| **级联挤第二次** | 我的驱动拿"当前段"当原文再挤一次 → 内核整发拒收两发 | 加一手名单 `FOLD_DONE`，挤过的段不再挤；不能挤时明写"本轮没有可挤的历史段"，不硬造 |
| **`(8)` 系把 dropped-whole 的措辞写死** | 挤尾真发生时必红 | 期望正文改由**一份** `pick_notice(kinds)` 产生，装配与判定共用（各写一遍就会漂成两套期望） |
| **`(8)` 判定把所有发的挤法汇成一集** | 比对的是单发的通知 → 拼成 BOTH，判定的错 | 收窄到那一发的 `Cuts` |
| **`Notice.Sent` 由裁剪表单方面宣称** | 见下面第 7 节 | 改成从**真发出去的段**里读 |

真端点结果（5 发、`tokens_in=1858 / out=98`、账 235 条、`✓ 链自洽`、**被拒的写入 0 次**）：

```
(8)  第 3 发：clipped=1 段：history/第 2 发模型那句回答（挤尾留前缀）  挤法=['tail-dropped']  notice_sent=是
(12) 第 2 发原话 '27 加 15 等于 42。' 挤成 '27 加'
     账上 model_says=182e3adb56…   裁剪表记=530d81e837…   发出去那句=5987e4459a…
```

**三把指纹两两不同，在真模型的话上复现了**，不是在假端点那句定死的"和是 42。"上。
20 判定只剩 1 红，就是 `(12)` —— 这条缺口现在是**真端点复现过的**，不再是演示。

## 7. 顺带撞出来的第 14 条缺口的第一个真实例（不是伪造的）

第一版折叠逻辑我插在"附通知段"之后，于是有一发：裁剪表里多了一条 `tail-dropped`，
`Notice.Sent` 被写成"是"，而**真发出去的段里没有那句通知** —— 内核**照收了整发**。
这正是 README §8 那条一直只有推理、没有实例的缺口 14：
**`notice_sent` 与段表 `parts` 里有没有 `truncation-notice` 那一段，今天没有任何判据钉在一起。**

抓到它的是我自己新写的 `(8c)`（通知那一句得真占一段），不是内核。
修法是调用方侧的：`Notice` 那一格改成**从真发出去的段里读**，读不到就写 `Sent=False` 并带理由 ——
宁可让账读起来像缺东西，也不许写没发生的事。
