### 硬缺陷 3 条

**H1 — kaudit `/v1/tally` 把「不可知」印成六格全 0，且与同一份响应里的 `rejected_writes:null` 自相矛盾（规矩 2 · P0）**

- 位置：`cmd/kaudit/main.go:165` `"gate": s.journal.Gate`。`Journal.Gate` 是**值类型** `kernel.Gate`（`journal.go:200`），六格无 `omitempty`；没有计数栏时它是零值。`rejectedOrNull`（`main.go:245`）只护住了 `rejected` 一格（`:162` 印 null），可新加的 `gate` 对象把**全部六格**在没那一栏时也照印 0。
- 为什么是缺陷：这份改动立项的理由就是缺口 #51「`rejected_writes=0` 被第三方念成『闸门一次都没拦』」（改动单第 12-13 行、`:28`）。它给 `rejected` 修好了（null），却在同一次改动里给其余五格（含另一个 `rejected`）重新造了同一个形状。`gate_line:false`/`gate_state:"不可知"` 是旁证字段，不等于 `gate.rejected:0` 不会被读成一个「量到的 0」——同一份 JSON 里 `rejected` 既是 null 又是 0，两句话，直接违「量到的 0 与不可知要说两句话」。
- 复现（已跑，非静态）：临时程序 `gatecheck` 载一份无 gate 栏的账 → `/v1/tally` 构造的 map 印出：
  `{"gate":{"rejected":0,"precheck_rejected":0,"precheck_door":0,"door_refused":0,"bad_requests":0,"transport_refused":0},"gate_line":false,"gate_state":"不可知（手里这份字节里没有计数那一栏）","rejected_writes":null}`
- 修法：`gate` 用指针 `*Gate`，`!HasGate` 时印 `null`；或给 kaudit 一个 `gateOrNull(j)`（同 `rejectedOrNull` 的判据、同一个 owner：`j.HasGate==false ⇒ nil`），六格一起三态化。
- 验收判据：新增一支 kaudit 测试，载一份无 gate 栏文件打 `/v1/tally`，断言 `gate == null`（且 `rejected_writes == null`），断言**没有**任何一格被印成裸 0。目前 `cmd/kaudit/main_test.go` **一支**断言 tally 的 gate 输出的测试都没有（只在 `TestAuthRequiredAndSilent` 里拿 tally 端点验 401 不漏内容）——见第四节。

**H2 — 三态（Partial=下界 / Unknown）根本落不了盘：`只覆盖这一程` 重编再读回被洗成 `这一程完整可数`（规矩 2 · P0；且是实现相对改动单删了 `known` 位的回归）**

- 位置：落盘的 `gateLine` 结构（`journal.go:91-96`）字段只有 `gate/chain_head/gate_sha256/gate_version`，**没有任何表达三态的位**；`LoadLedger` 判口径完全只看这一行在不在：`journal.go:502-507` `if j.HasGate { … gateState = GateLive } else { GateUnknown }`。`Partial` 只能由内存里 `touchGate`（`kernel.go:304`）在「从 Unknown 记账」时升出来，**永远不会从盘上读出**。
- 为什么是缺陷：改动单第 21、23 行原话是要加 `countersKnown bool`、gate 行里带 `known:true`。实现的 `Gate`（`kernel.go:128-135`）和 `gateLine` 都**没有这一位**。于是 `GatePartial` 的「这是下界、前面不可知」这句（`kernel.go:143-145`、contract.md §2.3b line 16「三种说法能说的话不同」）**在落盘这一步被抹平**：任何一本带 gate 栏的文件读回一律 `Live`。
- 复现（已跑）：`gatecheck` 里 ① 载一份无 gate 栏账 → `GateStatus=不可知`；② `NotePrecheckRejected()`×3 → `只覆盖这一程`（PrecheckRejected=3）；③ 把这本重 `MarshalJournalWithGate` 编出去、再 `LoadLedger` → **`HasGate=true`、`GateStatus=这一程完整可数`、PrecheckRejected=3**。下界被念成全量。④ 印出落盘 gate 行顶层键只有 `[gate chain_head gate_sha256 gate_version]`，gate 子键只有那六个数——没有任何槽位能带 Partial/Unknown。
- 外壳可达路径：`mcpsrv.go:470` `encode_journal` 无条件用 `gateNow()` 落 gate 行。外部调用方只要 `load(无栏) → 记几笔 → encode_journal` 再交给别人读，别人拿到的就是 `Live`，把「本程数到的下界」冒充成「这一程完整可数」。
- 修法：gate 行补 `state`/`known` 字段（按改动单原案），`LoadLedger` 按它恢复三态；或在 `!GateLive` 时禁止 `encode_journal` 落 gate 栏（宁可落回「没有这行=不可知」，也不落一个会撒谎的 `Live`）。
- 验收判据：新增一支往返针：load 无栏 → 计 3 笔（Partial）→ re-encode → re-load → 断言 `GateStatus==GatePartial`（**不是** Live）。这条今天必红。

**H3 — `load_journal` 的拒绝回话把不同单位的数合起来、还把两笔「门口」并成一笔，并对带栏文件谎称「变成不可知」（规矩 1 + 规矩 2）**

- 位置：`mcpsrv.go:499-501`。
  - `liveGate = Rejected+PrecheckRejected+precheckDoor+doorRefused+badRequests+transportRefused`（`mcpsrv.go:495-497`）被渲染成 `"闸门计数 %d 笔"` —— 把六个**不同单位**（发/发/一次请求/一次写请求/一条请求/一条请求，见 `kernel.go:119-124`）加成一句「N 笔」。这正是 contract.md §2.3b line 14「六笔数单位不同，永不相加……合起来就答不出『谁拒的』」明令禁的。`liveGate>0` 当**布尔**用没问题；错在把它当一个数**印**出来。
  - `"门口 %d"` = `precheckDoor.Load()+doorRefused.Load()`（`mcpsrv.go:501`）—— 把「预检门口」和「落账门口」两笔（单位也不同）并到一个「门口」标签下。而 `tally`（`mcpsrv.go:403-404`）与 `gateReadout`（`mcpsrv.go:774`）都**刻意把这两笔分开**说（「预检在门口被挡下」/「落账门口挡下」）。同一轮改动里 load_journal 是唯一合并它们的出口 ⇒ 也违「一个读数只有一个 owner」的口径。
  - 结论句 `所以换完那些数不是归零、是**变成不可知**`（`mcpsrv.go:506`）无论 `j.HasGate` 真假都印。手里文件**带着计数栏**时，替换后那些数是「文件里的已知数」，不是「不可知」。
- 复现（已跑）：一个进程做 1 次门口挡下的预检（链仍 0 条、liveGate=1），`encode_journal` 出的字节**带着 gate 栏**，再把它 `load_journal`（不带 ack）→ 拒。回话原文：
  `载入被拒：这本账现在有 闸门计数 1 笔（拒落账 0、拒预检 0、门口 1、协议层 0、传输层 0），载入会把它们换掉（不是合并）；手里这份文件带着计数栏，所以换完那些数不是归零、是**变成不可知**。确认要丢就带 acknowledge=replace`
  ——「带着计数栏」与「变成不可知」自相矛盾；「闸门计数 1 笔」是合出来的；「门口 1」若两笔都非零会被并。
- 修法：拒绝句逐笔列、不给合计数（把 `liveGate` 只当布尔、`门口` 拆成 `预检门口/落账门口`）；结论按 `j.HasGate` 分两支（带栏⇒「会被换成文件里的数（口径=文件带的）」，无栏⇒「会变不可知」）。
- 验收判据：断言该拒绝回话里**不含**「闸门计数 <数字> 笔」这种合计数、**不含**把 `带着计数栏` 与 `变成不可知` 并排的句子；带栏文件的拒因说「变已知（另一组数）」。

## 四、这份改动里最可能假绿的一处
