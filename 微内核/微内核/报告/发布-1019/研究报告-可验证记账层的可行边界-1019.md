## §0 决策摘要

### 0.1 三个结论

**第一，技术资产是真的，但它的形状是“收口件”，不是“引擎”。**
它能把一次 Agent 调用拆成 49 格，逐格要求“值 + 出处”，把“没量到”和“量到了 0”分开，任一格不自洽就整发拒收，账本用哈希链串起来。这些不是 PPT：80 根慢闸整轮跑过，空针/坏针 0；独立复算 80/80；对照臂会红（§3，E2）。但同一份证据也说明，这次盲测没有显示它提升任务成功率——8 题里纯模型 8/8、带内核 6/8（§4，F1）。它管的是“说出来的话有没有出处”，不是“活干得好不好”。

**第二，当前唯一验收过不了，原因不是实现差，是判据设计错了。**
唯一验收三句话，今天各有一处硬伤：

1. “被拒的写入 ≥ 1”奖励的是调用方犯错，不是闸门有效。一个背过契约的调用方可以 0 次被拒；一个乱填的调用方可以轻易满足。它没有对照臂，分不清“闸门抓住了一条坏记录”和“调用方本来就不会填”。
2. “任何一格都不许没量到却写成 0”是一句全称命题，而结构上做不到：字符串格与一批计数格根本没有“缺席”的写法；#66 只把 `Cuts` 这一族修成两句不同的话，不是全部（§4，F3）。
3. “一个不是我写的真人接上”今天真人接手 0 次；此前的第二个调用方是作者自己写的，外部评估者是 AI 调用方，不是“没参与过这个项目的人”（§4，F4）。

**第三，市场空位存在，但不是“更可信的 Agent”。**
MCP08“缺乏审计与遥测”是标准里的真缺口，但已经有网关 / 控制面厂商在做；电商“承诺可追溯”是真需求，但它记的是“承诺”，这颗内核记的是“模型调用”，单位不对。真正与它形状匹配的空位是：**一次 Agent 跑完之后，用很少的调用换一份可复核、可拒收、可读回的交代。** 这是一个收口件，不是一个常驻引擎，也不是承诺记账产品。

## §1 问题：Agent 的“说法”没有价格

### 1.1 一个场景

一个 Agent 告诉你：“12 个商品页都改好了，价格都核对过。”
你打开日志，看到 12 条工具调用。日志能证明“调用发生过”，但不能证明：

- 它说的“核对过”对应哪一次调用、哪个价格源；
- 12 个页面里有没有哪一格其实是“没量到”，却被写成了 0；
- 它引用的那个计数，是它自己算的、上游转述的、还是模型自己说的；
- 它被闸门拦过几次、拦在哪一格。

这四件事，普通日志都不管。它们不是“可观测性”问题，是**记账形状**问题。

### 1.2 两种失效形态

**第一种：说法漂白。** 上游一个没有依据的计数，被下游当成证据写进结论。这个仓库的 `kernel.go` 头部第一条不变量就是为这件事写的，来源是一次真事故（`产品定位.md:46`）。说法一旦被写进一份看起来正式的记录，后面的人就会把它当事实继续引用。

**第二种：事后拿不出。** 事情做完，只有聊天记录和零散日志；要回答“当时到底量到了什么”，只能靠回忆。回忆不是证据。

这两种失效的共同点是：**说错话的成本太低，而证明说错话的成本太高。** 这颗内核的全部设计，就是把“说错话”变成一次可以被当场拒收的写入。

### 1.3 2026 年的外部背景

这一节的事实是 D 级外部资料，不是内核读数。

- **MCP08“缺乏审计与遥测”已经是标准条目。** OWASP MCP Top 10 对它的描述是：MCP 服务器与 Agent 的遥测有限，阻碍调查与事件响应。原文：*“Limited telemetry from MCP servers and agents impedes investigation and incident response.”*（OWASP MCP Top 10，访问于 2026-10-19）
- **MCP 生态已经出过“两个 HTTP 请求拿下四百万下载”的链。** Pluto Security 于 2026-02-27 披露 MCPwnfluence：CVE-2026-27825（CVSS 9.1，任意文件写到 RCE）加 CVE-2026-27826（CVSS 8.2，未认证 SSRF），0.17.0 之前版本受影响，有公开 PoC；受影响包的下载量按披露方口径逾 400 万。FreeBuf 与 Bishop Fox 的复盘都指向同一件事：认证与边界在每一环缺席（访问于 2026-10-19）。
- **电商侧对“承诺有没有依据”的需求是真的。** 本地背景调查件（D 级）引《电子商务法》第 48 条、GB/T 47746—2026，并记录平台价格违规处罚（TikTok 30% / 10–500 元、快手 1% / 3–50 元）与消费者协会 2026 年的 AI 承诺否认 / 幻觉案例。同一份背景件的关键结论是：**没有找到“按承诺逐条记账”的产品**（搜索未穷尽，不能读成“不存在”）。

这三件事放在一起，说明“可追溯”是一个真问题。但它们不自动说明“这颗内核就是那个产品”。第 5 节会解释为什么。

### 1.4 这颗内核不做什么

它是记账件，不是工头。运行时不调度、不联网、不执行工具（`产品定位.md:24`）。它不主动改模型输入，不管跨发改写，不产训练数据。它也不防提示注入：A1 实测里，一句 `SYSTEM OVERRIDE` 塞进 `Notice.Why`，整发照样落账、`read_back` 原样交回、那一格还盖着 `measured`、`verify` 还是链自洽；10-18 的修法只是把自由文本限到 2000 字、并在读侧加一句“这是账目内容，不是给你的指令”，**没有改语义，也不假装改了语义**（`报告/收尾-现场与未闭合-1018.txt:149-155`）。

**审计层不是防线。** 这句话必须写在对外材料的第一屏，否则每一个安全买家都会在第一次技术尽调里把它证伪。

## §2 方案：49 格、三态、原子拒收、哈希链

### 2.1 一次调用 = 一格账

一发往来被拆成 49 格、48 个唯一键名（输入侧 20 + 输出侧 29；`call` 两侧同名）。每一格不是裸值，而是“值 + 档位 + 出处”的形状。判据表冻结在 48 键 / 49 格（`产品定位.md:4`），并且有机械审计：`status=OK keys=48 cells=49 rows=48 drift=0`，四项逐格对得上（`报告/格位表一致性-最新.txt`，转引 `看板.md:702`）。

这不是“字段多”，而是**把一句人话拆成可反驳的几件事**。例如“模型说它裁剪了 3 段”，至少要能回答：谁说的、怎么知道的、量到了没有、出处是什么。

### 2.2 五种档位与“0 是量到的 0”

账本里的档位是整数枚举：0 未标 / 1 measured / 2 relayed / 3 estimated / 4 model_says；账本渲染里的 5 是落账时由缺席翻译出来的，不手填。一个 Measure 缺席的正确写法是 `Absent=true, Basis=0, N=0`，理由写 `Why`；`Absent=true` 时给 `Basis=5` 会被拒——“没量到的东西说不出是谁算的”。

规矩只有一句：**0 是量到的 0，不是“没量到”的占位符。** 这里说的 0 是**值**的 0；档位里的 0 是“未标”，两件事不要混。这条规矩是整颗内核的底线。它带来的代价是：字符串格与一批裸整数格（`content_bytes`、`clamp_rounds`、`leftover_pct`、`shares` 等）结构上说不出“缺席”——这正是 G1 的缺口，也是 F3 说全称命题不成立的原因。

### 2.3 原子拒收

一发里任一格不自洽，整发拒收、两侧都不写、拒收另计一格。外部调用方的实测里，它那 6 发 = 294 条，整本账 490 条；每发落 49 条，没有出现非 49 倍数的半发（`报告/外部评估-主页圈-aec6dd94-对账-1018.md`）。注意：490 里面另有 196 条属于一条与本调用方无关的 session，**不能把整本账的增长全记在它头上**。这不是“尽量不写坏数据”，而是“坏数据一条都不写”。

### 2.4 哈希链与 append-only

账本每条带前序哈希，`verify` 能逐条比对原像。外部评估的 6 发全部能按 session + 发号 + 侧读回，逐发指纹与盘上文件对上；它没有回改旧发（`对账-1018.md` 第三节）。这证明的是**链的完整性**，不是**内容的真实性**：链能证明“这条记录没有被改过”，不能证明“记录里那句话是真的”。

### 2.5 唯一 KPI

产品只有一个 KPI：六笔闸门计数——写入被拒、预检拒收、预检门挡、落账门挡、协议层、传输层。六笔单位不同，**不相加**。每一笔还要带 `GateState`：未知 / 只覆盖本程 / 完整。零值不是“0 次”，是“未知”。

10-18 之前，预检那一路一个数都不记；10-18 起才真的兑现（`产品定位.md:58`）。但“记数”只修了半边：拒收回话里“是哪一格”仍是一句人话，没有结构化格名——这是 #48，仍是开的。

### 2.6 运行边界

- 不调度：没有循环、定时器、cron；`time.Ticker` / `time.AfterFunc` / cron **0 处**。
- 不联网：不调模型、不取外部数据；`http.Get` / `http.Post` / `http.Client` / `net.Dial` / `url.Parse` **0 处**。
- 不执行工具：运行时没有 `exec`；唯一一次 `exec` 是构建期的依赖自检（`isolate.go:336`）。
- 只做两件事：MCP 监听 + 账本 I/O。

这些边界让它容易审计，也让它无法单独成为一个“Agent 平台”。它必须挂在别人的循环上。

### 2.7 两种产品形态：常驻 vs 收口

外部调用方的实测给出了两种成本形状：

- **常驻记账**：整圈挂 + 逐格声明，约 130 次调用，其中约 110 次花在记账上；发 1 / 发 2 的 `tool_calls` 是 77 / 25。
- **收口一发**：干活时不记账，收口只落 1 发；写文档 1 + 量字节 1 + 落账 1 + 读回 1 + verify 1 + tally 1 = **6 次调用，0 次预检**。

这两个数是调用方口述（B/C 级），没有被独立复算；但形状是可复核的：同一份判据在收口发里已经由前两发验过，不必再交预检税。**常驻的成本约是收口的 4 倍。** 这是“收口件”定位的经济学依据，不是产品口号。

**能说**：链的完整性、读回、读者声明、原子拒收，在一个真实的 AI 调用方身上走通过。
**不能说**：语义内容是真的；也不能说换一个人、换一类负载还成立。这是一次外部实测，不是市场验证。

这里还有一处容易混的分母：**48/49 是“调用方声明了读者”的格数；G3 说的 3 格（`model_says_clipped` / `sent` / `cost_countable`）是“非测试 Go 源码里 0 读者”。** 一个测“有没有人声明读”，一个测“代码里有没有人读”；两者不是同一件事，不能互相抵消。

### E5 收口成本有一个可复现的形状（B）

> `6 次调用：写文档 1 + 量字节 1 + 落账 1 + 读回 1 + verify 1 + tally 1；0 次预检`
> `130 次调用里约 110 次花在记账上`
> `发 1 / 发 2 tool_calls 77 / 25`
> —— `报告/外部评估-主页圈-aec6dd94-原文-1018.md:50,38,51`

**能说**：收口件的成本形状成立；常驻约是收口的 4 倍。
**不能说**：这些调用数是独立复算的。调用方自己明说“预检被拒的确切次数在 24–26 次之间，给不出准数”（同件 :56）。所以 6 / 130 / 110 / 77 / 25 都只能引用成“调用方口述”，不能引用成实测。

### E6 唯一 KPI 的旧账四栏全 0，10-18 修了计数半边（A / B）

> `被拒的写入 / 门口挡下 / 协议层 / 传输层 四栏全 0`，而同一条链上有 10 发真账（490 条）。
> —— `报告/外部评估-主页圈-aec6dd94-对账-1018.md`

> `这是产品的唯一 KPI。10-18 起它才真的兑现：原先预检那一路一个数都不记`
> —— `产品定位.md:58`

修法是 `gateNow()` 的聚合口径 + 一条测试 `TestAggregateGateStateCoversShellCounters`（`报告/收尾-现场与未闭合-1018.txt:177-180`）。

**能说**：在 10-18 之前，产品对外的“拦了几次”是答不出的；现在计数半边有了。
**不能说**：点名半边也有了。拒收里“是哪一格”仍是人话（#48 / G5）。旧账里的预检拒收永远补不回来——那 24–26 次是 C 级口述。

### E7 安全面：一条已修、三条默认关、一条没测（A）

- **A1 注入载体（已修）**：`Notice.Why` 塞入 `SYSTEM OVERRIDE`，整发落账、原样回显、`measured`、链自洽；修法是写侧 `MaxFreeText = 2000`，读侧 `instrShapeTag` 只加提示，不改存储字节；配 6 条测试，`kcheck` 36 → 40 项（`收尾-现场与未闭合-1018.txt:149-155`）。
- **A2 回环无鉴权写入（默认关的开关）**：本机任意进程都能落假账 / 读整本账；`actor`、`session` 全是自报字符串（同件 :156-157）。
- **A3 毁账两次调用即可（默认关的开关）**：`load_journal` 是替换；空文 + `acknowledge=replace` 能抹掉 49 条（同件 :158-159）。
- **A4 涨账无上限（默认 0 = 不拦）**：60 发合法记账 105ms、账涨到 2940 条；没有条数上限也没有速率限制（同件 :160）。
- **A5 畸形输入打不死服务（GOOD）**：负发号、超大数、错类型、非法 UTF-8、空参数都进拒收分支（同件 :161-162）。
- **没有 `go test -race`**：本机没有 gcc/clang，cgo 失败 ⇒ 并发那半只有源码形态结论，不是观测（同件 :126,163）。

**能说**：A1 的形状修了；A2/A3/A4 有默认关的开关；A5 的畸形输入面、A6 的静态面干净。
**不能说**：默认部署已经安全。默认全关 = 现状一字不变；A2/A3/A4 仍然在。也不能说“防注入”：A1 只限长、只加提示，不改语义。

### E8 交付与过程：包里的凭据不是包里的二进制（A）

> 三份凭据的 zip 内时间都是 10-18 23:35，包里的 exe 是 10-19 的字节；打包器只复制 `日志/`，从不重跑。
> —— `报告/行为缺口目录与外部接入自证清单-1019.txt` G8

> `打包.py:11` import subprocess、`:319` 是全文件唯一一次（跑解包出来的 `bin/kcheck.exe`），`:17` PKG=交付树、`:235` `walk_files(PKG)` 只收现成的 `bin/`、`:254-258` `copy2` 搬字节 ⇒ **它从不编译**。
> —— `看板.md:288`

**能说**：包内凭据与包内二进制不是同一天的产物；zip 哈希绿不等于交付可信。
**不能说**：所有包都过期；但 G8 这一条足以让“可复现交付”这句话今天不成立。

### F2 唯一验收第 1 条：奖励天真，不奖励闸门（A）

验收原文：

> 账上 `被拒的写入 ≥ 1`，且每一次都能指名是哪一格拦的、内核原话是什么。
> —— `产品定位.md:80`

问题有两层：

1. 如果“被拒的写入”指落账门（`rejected`），一个背过契约、填得干净的调用方可以 0 次被拒——它会被这条判失败，而它恰恰是闸门最该服务的用户。
2. 如果它把预检拒收也算进去，一个故意乱填的调用方可以轻易满足——它会被这条判通过，而它证明的只是“调用方会犯错”。

外部实测正好落在两层之间：8799 的 `被拒的写入 / 门口挡下 / 协议层 / 传输层` 四栏全 0，而调用方口述有 24–26 次预检拒收；这些拒收在旧账上不落账（`对账-1018.md` 第五节）。所以这条判据既不能证明闸门有效，也不能证明调用方干净。**它没有对照臂。**

### F3 唯一验收第 2 条：全称命题不成立（A）

验收原文：

> 全程链自洽、`sk-` 0 次、任何一格都不许出现“没量到却写成 0”。
> —— `产品定位.md:81`

- 字符串格与一批裸整数格没有缺席档位；它们的 0 分不清“量到 0”和“说不出口”。

- G4 的接线覆盖率是 10/11；G3 有 3 格“登记了但除登记外没人念”。

**能说**：`Cuts` 这一族已经能分开；这是一次真进步。
**不能说**：第 2 条已经全守住了。把 #66 的完成读成“任何一格都行了”，是把一次局部修复读成了一条全称承诺。

### F4 唯一验收第 3 条：真人接手 0 次（A）

> 今天真人接手 0 次 —— 这个数字有脚本自印

> —— `报告/行为缺口目录与外部接入自证清单-1019.txt` G10

**不能说**：永远找不到人。它只说明“今天没有”，不说明“不可能”。

> 能数出多少条人话与代码标签逐字同名（撞得上 5 / 撞不上 3）
> 不能说『每一次拒收都能机核是哪一格』：那半是 NOT_CHECKABLE

### F6 `kcheck` 在没 go 的机器上降级，退出码仍是 0（A）

**不能说**：默认部署已经安全。也不能拿“审计层”去回答“防不防攻击”——它不防。

## §5 市场与竞争：三个需求层，一个空位，五种死法

### 5.1 需求层一：MCP 审计与遥测

MCP08 把“审计与遥测缺失”写进了标准。这个缺口是真的，但它正在被平台吸收：微软的 Agent Governance Toolkit 已经把“Audit logging + metrics collection hooks”对到 MCP08；控制面 / 网关厂商也在做同样的事（Microsoft，2026-04-29；访问于 2026-10-19）。

这至少说明：**“我有审计日志”很难单独卖，它更像一个网关功能。** 微软已经把“Audit logging + metrics collection hooks”对到 MCP08；这颗内核如果把自己定位成“MCP 审计层”，它会在第一次采购里被问三个问题：你有没有鉴权？有没有限流？有没有 race 测试？这三个问题今天都答不好（A2/A3/A4、无 race）。

它真正不同的地方不是“有日志”，而是：**逐格要求说法带出处、缺席不带数、任一格不自洽就整发拒收。** 这是“记账形状”，不是“遥测”。但如果买家只想要“能查”，他不会为这个差异付钱。

### 5.2 需求层二：Agent 可观测性

可观测性厂商记录 trace、span、token、延迟、错误。它们回答“发生了什么”，不回答“这句话是谁算的、有没有量到”。这颗内核补的是后一层。理论上二者可以互补：trace 给你路径，记账给你每一句说法的出处。

现实里，互补不等于可卖。可观测性买家已经有一套采集、存储、查询、告警的栈；他不会为了“49 格说法”再接一个进程、改调用方、承担 130 次调用的记账成本。**除非**这个差异正好是他要向第三方交代的东西——例如一次交付、一次审计、一次事故复盘。这就是收口件的场景，不是常驻件的场景。

### 5.3 需求层三：电商承诺记账

这是最诱人的一层，也是最容易走错的一层。

本地背景调查件（D 级）记录了真需求：平台对价格违规有明确处罚，法规与标准要求可追溯，消费者协会已有 AI 承诺否认 / 幻觉案例；同时，**没有找到按承诺逐条记账的产品**。这看起来像一个空位。

但单位不对：

- 这颗内核记的是 **一次模型调用的 49 格**；
- 电商要的是 **一句对客承诺的证据链**（谁说的、什么时候说的、依据哪个价格 / 库存 / 规则、事后有没有兑现）。
- 一次承诺可能跨多次调用、多个工具、多个人；一次调用也可能包含多句承诺。49 格与“承诺”不是一对多的关系，是两个不同的本体。

要把它变成承诺记账，需要一个新的上层：宿主在“承诺发生时”发事件，内核记“承诺事件”，而不是“模型调用”。这不是加一格，是另一个产品。今天没有这个宿主，也没有伙伴；悟空线已经关闭，且官方页面上没有审计 / 日志 / MCP / API 这些词（下载站的“可追溯”是 L3 说法，未验证）。所以 B 路线现在不可行，不是因为它不吸引人，而是因为它的最小可行形态不在这颗内核里。

### 5.4 空位与占位

| 位置 | 谁占着 | 这颗内核能不能占 | 结论 |
|---|---|---|---|
| MCP 鉴权 / 网关 | 平台与控制面厂商 | 不能：A2/A3/A4 默认关，无 race | 不做网关 |
| MCP 审计日志 | 已有网关 / 控制面厂商在做 | 只能做“说法-出处”差异层 | 不做通用日志 |
| Agent trace / 可观测性 | 现有 observability 栈 | 可作为补充，不可替代 | 不做 trace |
| 一次任务后的可复核交代 | **空位** | 能：约 6 次调用、原子拒收、读回 | **收口件** |
| 按承诺逐条记账 | **空位，但单位不对** | 不能直接占 | 另一个产品 |

### 5.5 五种死法

1. **“更聪明的 Agent”**：F1 已经给出负结果。买家按任务成功率选型，不会为 6/8 买单。
2. **“更安全”**：审计层不是防线；A1 只限长、只提示；A2/A3/A4 默认关；没有 race。安全买家第一次尽调就会把它归到“日志”而不是“防护”。
3. **“平台级合规”**：没有宿主、没有承诺级事件、没有伙伴；平台自己的价格风控是交易前规则，不是事后记账。
4. **“常驻记账”**：130 次调用 / 约 110 次记账，约 4 倍成本；除非有外部报数义务，否则没人愿意常驻。
5. **“标准 / 开源”**：49 格是一份可读的契约，但没有社区、没有实现生态；网关厂商可以吸收它的差异点，而它没有分发。

### 5.6 研究资产的价值

即使产品不卖，以下资产是真的：

- **49 格契约**：一份可机核的“说法形状”规范；
- **三态纪律**：0 是量到的 0，缺席有缺席的写法；
- **可红的尺子**：80 根针、独立复算、对照臂；
- **失败档案**：#66、#48、G1、G7、G8 这些缺口，以及它们被怎么发现、怎么修、怎么仍然没修完。

这些可以出版、可以做培训、可以做成审计清单。它们不要求买家安装一个进程，也不要求作者再维护一个产品。**这就是 C 路线的价值：它不是失败后的退路，它是把已经付出的证据成本变成可复用资产。**

## §6 可行路径：三条路线与一把新尺子

### 6.1 可行性矩阵

| 运营：交付 | **低–中** | F6 / F7 / F8；无 race；单人 | 重打包 + 凭据对齐；读侧拒错键；退出码语义 |
| 商业：买家 | **未证** | F10；无可数买家；MCP08 被吸收 | 设计伙伴；付款证据；定价 |

### 6.2 A 路线：收口件

**一句话承诺**：在你已经做完一件事之后，用约 6 次调用把“发生了什么”记成一份可复核、可拒收、可读回的账；不改你的模型代码。

**不承诺**：不让 Agent 更聪明；不挡提示注入；不做实时调度；不替代日志 / 追踪；不保证业务承诺是真的；不做网关。

**最小形态**：

1. 一次任务结束，调用方只落 1 发；49 格能填的填，填不了的按缺席写，不借名。
2. 落账前可选 `check_call`；收口发可以免预检税（同一份判据已验过）。
3. 落账后 `read_back` + `verify` + `tally`，交一份三件套：账、链、读数。
4. 读者声明只给结论地基那几格，不逐格凑。
5. 默认不常驻；需要常驻的场合，先证明有外部报数义务。

**它需要的验收**：不是现在的三句话，而是 §6.4 的双臂。

### 6.3 B 路线：承诺记账

**吸引力**：法规、平台处罚、消费者投诉都是真的；按承诺逐条记账的产品没有找到。

**为什么现在不可行**：

- 单位不对：模型调用 ≠ 业务承诺；
- 没有宿主：没有人在“承诺发生时”发事件；
- 语义真值不在内核：内核只核形状，不核“这句话是否符合事实”；
- 悟空线已关，且没有可验证的审计 / MCP / API 面；
- 需要伙伴与合规销售，这不是零成本路径。

**什么时候重开**：出现一个宿主（交易 / 客服 / 商品系统）愿意在承诺发生时发事件；出现一个买家带着明确的合规截止日；出现一个伙伴拥有语义真值层。三者至少有两个，再谈。

### 6.4 双臂验收：替换“唯一验收”

#### 为什么要换

现有三句话把三件事混在一起：调用方会不会填、闸门会不会拦、有没有外人接。结果是一条也证明不了。双臂验收把它们拆开：

- **干净臂**测“外人能不能接上”；
- **坏臂**测“闸门能不能抓住已知的坏”；
- **对照**测“闸门不是什么都拒”。

#### 干净臂（由一个没参与过本项目的真人跑）

通过条件：

1. 在 ≤30 分钟内完成一次真实任务，调用方模型代码零改动。
2. `verify` 链自洽；`sk-` 0 次。
3. 每一格要么“值 + 出处”，要么“缺席 + Why”；Measure 格不许出现“没量到却写成 0”。
4. `readers_report` 能说清哪些格有读者、哪些格没人读；没人读的格必须被明写，不许沉默。
5. `tally` 的六笔计数带 `GateState`（未知 / 只覆盖本程 / 完整），不许把 0 当“0 次”。
6. **不要求 `rejected ≥ 1`。** 一个干净的调用方可以 0 次被拒；这正是它该有的样子。

#### 坏臂（由脚本或测试者注入两条已知的坏记录）

1. **语义坏**：`Basis=3`（估算）但不给 `Source` → 必须被拒；计数进入正确的桶（落账门或预检拒收，按路径定）；拒收必须点名是哪一格。
2. **格式坏**：同一个 `(reader, key, side)` 重复声明 → 必须被拒；计数进入 `tally` 六笔里正确的那一桶（桶名按实现定，不相加）；拒收必须点名重复。
3. **对照**：把同一条语义坏记录补上 `Source` → 必须被收；把重复声明换成一个新读者 → 必须被收。**闸门不许变成“什么都拒”。**
4. 坏记录一条都不许进链；链仍然自洽。
5. **可选：篡改臂**。改一条已落账的行 → `verify` 必须报不一致；在 append-only / 口令开启时，`load_journal` 必须拒。今天默认关，所以这一臂只能作为“开关打开时”的验收，不能作为默认部署的验收。

#### 通过判据

- 干净臂 1–5 全过；
- 坏臂 1–4 全过（篡改臂若默认关，标“未覆盖”，不许标“过”）；
- 两条臂的计数不互相污染；
- 拒收点名：如果 #48 还没修，只能做字符串匹配，必须在验收里明写“这是弱判据”；如果补了结构化格名，才能机核。

#### 这把尺子比原来的强在哪

- 它不奖励天真：干净臂允许 0 次被拒；
- 它有对照：坏记录必须被拒，好记录必须被收；
- 它把“外人能不能接上”和“闸门能不能拦”分开；
- 它能在今天的内核上跑，不需要新增 49 格中的任何一格；
- 它仍然诚实地说出自己不能证明什么：语义真值、业务承诺、注入防护、真实买家、并发安全。

#### 它还需要的前置

- **#48**：要么补结构化格名（动判据表，要三件套），要么接受字符串匹配并把“弱判据”写进验收；
- **KPI 计数半边**：确认预检拒收在正确的桶里，且 `GateState` 不被 0 冒充；
- **G7**：验收不许用 `kcheck` 的退出码当“全绿”；必须读三态；
- **G8**：重打包，凭据时间 ≥ 二进制 mtime；
- **G6**：如果要跑 `load_journal` 臂，先修读侧错键静默空账，否则这一臂标“未覆盖”。

## §7 对外白皮书草稿

> 这份草稿是给外部读者看的，约 1,800 字。它只使用本报告里 A/B 级证据；D 级外部事实标注“公开资料”。它是草稿，不是已发布稿。

### 当 Agent 说“我做完了”：为什么我们需要可验证的记账层

一个 Agent 告诉你：“12 个商品页都改好了，价格都核对过。”
你打开日志，看到 12 条工具调用。然后呢？

日志能证明调用发生过，却不能证明它说的“核对过”对应哪一次调用、哪个价格源；不能证明 12 个页面里有没有哪一格其实是“没量到”，却被写成了 0；也不能证明它引用的那个计数，是它自己算的、上游转述的，还是模型自己说的。

这就是今天 Agent 落地时最容易被忽略的一层：**我们有很多“发生了什么”的记录，却很少有一份“这句话凭什么”的账。**

#### 日志不够，因为日志不要求出处

普通日志记录事件：谁在什么时候调用了什么工具、返回了什么。它不要求每一条结论都带出处，也不区分“量到了 0”和“没量到”。于是三种东西会混在一起：

- 真量到的 0；
- 没量到、但被默认成 0；
- 忘了填、被外壳补成 0。

一旦混进去，下游就会把一个没有依据的计数当成证据，继续写进结论。错误不是从“模型胡说”开始的，是从“记录里看不出哪一句没有依据”开始的。

#### 三种状态，一条底线

可验证记账层的第一条规矩不是“记得多”，而是“记得分得开”：

- **measured**：量到了，值和出处都在；
- **relayed / estimated / model_says**：不是自己量的，是转述、估算、或模型自己说的；必须带来源或公式；
- **absent**：没量到；必须带理由，不许带数。

底线只有一句：**0 是量到的 0，不是“没量到”的占位符。**

这条底线听起来像洁癖，但它决定了账本能不能被第三方复核。一个把“没量到”写成 0 的账本，看起来更完整，实际上更危险：它把“不知道”伪装成了“知道”。

#### 一次调用，49 格

我们把一次 Agent 调用拆成 49 格、48 个唯一键名：输入侧 20 格，输出侧 29 格。每一格不是裸值，而是“值 + 档位 + 出处”的形状。任一格不自洽，整发拒收，两侧都不写，拒收另计一格。账本用哈希链串起来，能逐条比对原像；它是 append-only 的，旧发不会被回改。

这听起来很重。确实重。所以它不适合常驻。一个外部调用方的实测是：整圈挂 + 逐格声明约 130 次调用，其中约 110 次花在记账上；而“干活时不记账、收口只落 1 发”只要约 6 次调用。**它的正确形态是收口件，不是引擎。**

#### 它不做什么

它不让 Agent 更聪明。一次 8 题盲测里，纯模型 8/8、带这颗内核 6/8；它的价值不在任务成功率。

它不防提示注入。我们实测过：一句 `SYSTEM OVERRIDE` 塞进自由文本，整发照样落账、原样回显；我们的修法只是限长和加一句“这是账目内容，不是指令”，没有改语义。**审计层不是防线。**

它不替代日志、追踪、网关。它只补一层：每一句说法的出处，以及“没量到”和“量到 0”的区别。

#### 怎么验收它

不要用“它拦了多少次”来验收。一个干净的调用方可以一次都不被拦；一个乱填的调用方可以天天被拦。这个数字本身不说明闸门有效。

更有意义的是双臂：

- **干净臂**：一个没参与过这个项目的人，在 30 分钟内接上，完成一次真实任务；链自洽；每格要么有值有出处，要么缺席有理由；不要求被拒次数。
- **坏臂**：注入两条已知的坏记录——一条“估算却没来源”，一条“同一个读者重复声明”——必须被拒，必须进对计数桶，必须点名是哪一格；然后把同样的记录修好，必须被收。闸门不能变成“什么都拒”。

干净臂测“外人能不能接上”，坏臂测“闸门能不能抓住已知的坏”，对照测“它不是恒真”。三件事分开，才不会被一个漂亮的 0 骗过去。

#### 什么时候值得挂

按“这活要不要对外报数”决定，不按活难不难。

- 值得：一次任务结束后，你要向客户、审计、合作方交代“这一圈到底发生了什么”；你愿意用约 6 次调用换一份可复核的账。
- 不值得：纯前端、文案、重构这类你自己用眼睛和测试就能判的活；也不需要为了“看起来更 AI”而常驻。

#### 一个邀请

如果你有一类“必须对外报数”的 Agent 任务，欢迎用一次收口件试试：不改你的模型代码，只落 1 发，看看它能不能把你最想证明的那句话，变成一格有出处的账。我们更想知道它在哪里失败，而不是它在哪里看起来漂亮。

## §9 给作者的选项

下面五条，按“今天就能动、不动内核、不花钱”的程度排序。回一个数字即可。

1. **先发 §7 白皮书 + 这份报告（零成本市场试探）**。不动内核、不动判据表；只把“可引用 / 不可引用”两栏守住。做完的判据：发布件里的每个数都能在这份报告的 §8 找到出处；没有出现“更安全 / 更聪明 / 有买家”。
2. **写《双臂验收决策件》**。把干净臂、坏臂、对照、#48 的两种走法（结构化格名 / 字符串匹配 + 弱判据）逐条写成可执行件，等你拍。做完的判据：两条臂各有一根会红的针，对照臂能证明“不是什么都拒”。
3. **只做交付完整性（G7 / G8 / F7）**。重打包并让凭据时间 ≥ 二进制 mtime；把 `kcheck` 的“核不了”与“过了”在退出码上分开；读侧错键当场拒。做完的判据：包内三份凭据的时间都晚于 exe；不带 go 的机器上 `kcheck` 不再用 0 冒充“核不了”；错键名 `load_journal` 返回错误而不是空账。
4. **转 B 路线（承诺记账）**。只做伙伴 / 宿主清单，不动内核；先找“承诺发生时”的事件源。做完的判据：至少两个外部条件（宿主 / 买家 / 语义层）有着落；否则关闭。
5. **冻结为研究资产（C）**。停止产品化与买家追逐；把 49 格契约、三态纪律、80 根尺子、失败档案整理成可出版件。做完的判据：出版物能独立回答“它是什么、不是什么、怎么验”，且不再承诺“可卖”。

**我的建议是 1 + 2，然后按 2 的结果决定 3 或 5；4 不启动。**
