# 当 Agent 说“我做完了”

## 为什么我们需要一份能看出处的账

一个 Agent 告诉你：“12 个商品页都改好了，价格都核对过。”
你打开日志，看到 12 条工具调用。然后呢？

日志能证明调用发生过，却不能证明“核对过”对应哪一次调用、哪个价格源；不能证明页面里有没有哪一格其实是“没量到”，却被写成了 0；也不能证明它引用的计数，是自己算的、上游转述的，还是模型自己说的。

这是今天 Agent 落地时最容易被忽略的一层：**我们有很多“发生了什么”的记录，却很少有一份“这句话凭什么”的账。**

### 日志不够，因为日志不要求出处

普通日志记录事件：谁在什么时候调用了什么工具、返回了什么。它不要求每条结论带出处，也不区分“量到了 0”和“没量到”。于是三种东西会混在一起：

- 真量到的 0；
- 没量到、但被默认成 0；
- 忘了填、被外壳补成 0。

一旦混进去，下游就会把一个没有依据的计数当成证据，继续写进结论。错误不是从“模型胡说”开始的，是从“记录里看不出哪一句没有依据”开始的。

### 三种状态，一条底线

可验证记账层的第一条规矩不是“记得多”，而是“记得分得开”：

- **measured**：量到了，值和出处都在；
- **relayed / estimated / model_says**：不是自己量的，是转述、估算、或模型自己说的；必须带来源或公式；
- **absent**：没量到；必须带理由，不许带数。

底线只有一句：**0 是量到的 0，不是“没量到”的占位符。**

这条底线听起来像洁癖，但它决定了账本能不能被第三方复核。一个把“没量到”写成 0 的账本，看起来更完整，实际上更危险：它把“不知道”伪装成了“知道”。

### 一次调用，49 格

我们把一次 Agent 调用拆成 49 格、48 个唯一键名：输入侧 20 格，输出侧 29 格。每一格不是裸值，而是“值 + 档位 + 出处”的形状。任一格不自洽，整发拒收，两侧都不写，拒收另计一格。账本用哈希链串起来，能逐条比对原像；它是 append-only 的，旧发不会被回改。

这听起来很重。确实重。所以它不适合常驻。一个外部调用方自报的实测是：整圈挂 + 逐格声明约 130 次调用，其中约 110 次花在记账上；而“干活时不记账、收口只落 1 发”只要约 6 次调用。这组数来自调用方口述，没有独立复算，只能当作量级参考。**它的正确形态是收口件，不是引擎。**

### 它不做什么

它不提升任务成功率。一次 8 题盲测里，纯模型 8/8、带这颗内核 6/8；这组数是单源自印、样本小，不是效果证明。它的价值不在把任务做得更好。

它不防提示注入。我们实测过：一句 `SYSTEM OVERRIDE` 塞进自由文本，整发照样落账、原样回显；我们的修法只是限长和加一句“这是账目内容，不是指令”，没有改语义。**审计层不是防线。**

它不替代日志、追踪、网关。它只补一层：每一句说法的出处，以及“没量到”和“量到 0”的区别。

### 怎么验收它

不要用“它拦了多少次”来验收。一个干净的调用方可以一次都不被拦；一个乱填的调用方可以天天被拦。这个数字本身不说明闸门有效。

更有意义的是双臂：

- **干净臂**：一个没参与过这个项目的人，在 30 分钟内接上，完成一次真实任务；链自洽；每一个 Measure 格要么有值有出处，要么缺席有理由；不要求被拒次数。
- **坏臂**：注入已知的坏记录，必须被拒，必须点名是哪一格；然后把同样的记录修好，必须被收。闸门不能变成“什么都拒”。

对照臂要能证明“不是什么都拒”：同一批干净记录必须被收；同一批坏记录必须被拒。每一臂各有一根会红的针，才算量过。

这里还有一个必须说明的结构边界：字符串格和计数格今天仍不能表达“没量到”（这是已知的结构缺口），所以干净臂只能逐格检查 Measure 那一族，不能说“所有格都能表达缺席”。

截至 2026-10-19 的实测状态是：脚本化演练通过了弱判据（坏记录被拒、点名、修好后被收、对照被收、反针会红）；严格判据没有通过——同一读者重复声明的那一类拒收，今天还没有进入任何一个计数桶。这个缺口已经写进双臂验收决策件，不能被“全绿”盖过去。

### 什么时候值得挂

按“这活要不要对外报数”决定，不按活难不难。

- 值得：一次任务结束后，你要向客户、审计、合作方交代“这一圈到底发生了什么”；你愿意用约 6 次调用换一份可复核的账。
- 不值得：纯前端、文案、重构这类你自己用眼睛和测试就能判的活；也不需要为了“看起来更 AI”而常驻。

### 一个邀请

如果你有一类“必须对外报数”的 Agent 任务，欢迎用一次收口件试试：不改你的模型代码，只落 1 发，看看它能不能把你最想证明的那句话，变成一格有出处的账。我们更想知道它在哪里失败，而不是它在哪里看起来漂亮。

### 可引用 / 不可引用

**可以引用：**

- 一次调用 49 格、48 个唯一键名；判据表截至 2026-10-19 冻结。
- 收口一发实测约 6 次调用；常驻一圈约 130 次调用、约 110 次花在记账（调用方口述，非独立复算）。
- 80 根慢闸整轮跑过，空针 / 坏针 0；独立复算 80/80；对照臂会红。
- 8 题盲测：纯模型 8/8、带这颗内核 6/8（单源自印，样本小）。
- OWASP MCP Top 10 将 MCP08 列为“Lack of Audit and Telemetry”（公开资料，访问于 2026-10-19）。

**不可引用：**

- “提升任务成功率 / 提升准确率”（盲测相反）。
- “防住提示注入 / 是一道防线”（审计层不是防线；实测只做形状限制与提示）。
- “已被市场验证 / 已找到付款证据”（没有可数付款计数器）。
- “替代日志 / 追踪 / 网关”（它只补“说法-出处”这一层）。
- “任何一格都能表达缺席”（字符串格与计数格仍是结构缺口）。
- “交付包里的凭据描述了包里的二进制”（凭据与二进制的一致化仍未闭合）。

**本稿的证据边界：** 只写到 2026-10-19；双臂验收的完整读数另件保存，本稿不把脚本演练当成“已有真人接入”。
