# wnh 内核 MCP（127.0.0.1:8799/mcp）优缺点与总结

评估对象：`mcphttp.exe`（pid 19176，`C:\Users\Admin\Desktop\微内核\构建-1017\便携包\agentkernel\bin`）经 MCP streamable-http 挂载，10 个 `kernel.*` 件，键名表 49 格（输入侧 20 + 输出侧 29，唯一键名 48）。
评估负载：一次真活——AI 科技公司主页生产（`index.html`，18,398 字节）+ 真浏览器验收 + 全链落账。
评估落笔时账上 294 条。**本文件每改一次就另落一发，不回改旧发（append-only）**：第 3 发=初版（7,676 字节），第 4 发=加建议清单版（16,804 字节），第 5 发=修正算术 slips。每条 `model_says_sha256` 对应的是**它那一发时的文件内容**，不是你此刻读到的这份；想知道当前文件落在第几发，用 `sha256sum` 与 `read_back` 逐发比指纹，别信正文里任何一句"当前版"。

## 一、优点（每条带本圈证据）

1. **三态分离是真判据，不是文档口号。** 「量到了 0 / 没量到 / 忘了填」三种形状在本圈被分别拦住：`Chunks` 整块没给 → 默认零值被读成"一帧都没收到"（而那恰好是协议错的判据）；补成 `Absent=true` 又因带出处被拒（"没量到的东西说不出是谁算的"）；最后 `Absent=true + Basis=0 + N=0 + 理由写 Why` 才过。三态各有独立判据，两头都拦。
2. **「没说」与「说了空串」分格。** `Finish(said=false, reason="stop")`、`Model(said=false, model="local-write-tool")` 两处当场被指自相矛盾。这两处我本来都会以"实测"口吻写进回复。
3. **公式只有一个 owner。** `ContentCeiling` 我手填 190000 → 拒收并回显公式（上限 200000 扣 15% 余量）；`LeftoverPct=7` 与 `shares` 相加=1 也被点名"两个数各算了一遍"。手搭预算进不了门。
4. **整发原子拒收。** 任一侧不自洽 → 两侧都不写，链上不多一条。本圈 24 次被拒（见第四节：这个数我给不出更准的），链上始终是干净的 49 的倍数：196 → 245 → 294。
5. **预检与落账同一份判据。** 实测 2/2：`check_call` 报"整发可落账"的载荷，`record_call` 全过。没有一次"预检放过而落账拒"。
6. **读侧可用是被证的，不是被声明的。** `read_back` 按 session+发号+侧读回 29 格，逐格给人话/出处/指纹；顺带逼出一次真产物核对：盘上 `4d8a22e6…` / 18,398 字节与账上 `model_says_sha256`、`model_says_bytes` 双对上。
7. **缺席有汇总。** `tally` 交档位分布（本圈后 absent=66 / measured=210 / model_says=6 / relayed=12），`readers_report` 交"49 格里几格没人读"，并明写"没人声明时它不是红，是待填"——不把缺口冒充结论。
8. **未知键不塌成 measured 0。** 拼错的键名整发拒收，且多数情况回显归一化候选（`Clipped` → 点名 `Cuts#clipped` 与 `Says.Clipped()` 两格，"我不替你猜"）。这一条直接封死"填错格子 = 假装量到"。
9. **键名表现场可要。** `celltable` 机械导出，不用抄文档——本圈我全靠它，抄 `contract.md` 反而错过一次。

## 二、缺点（每条带复现方式）

1. **对"活干得好不好"零判别力。** 49 格没有一格能承载"导航栏遮不遮字/配色对不对/文案能不能懂"。主页的验收全在 browser 侧（a11y snapshot、CSSOM、点击实测、控制台 0 条）。**它管的是传话层形状，不是产物质量。** 拿它的"链自洽"当"页面 OK"是两个结论串账。
2. **段名是 LLM 形态的闭合枚举。** `PartCount.Kind` 只认 system/skill/memory/history/toolspec/user；`Kind="content"` 被拒（"content 那一行报了 0 段"）。本地写文件、浏览器验收这两类发只能借这套名字，结果输入侧 6 行 `Bytes` 全 0，`part_totals` 在这类负载上零信息量。
3. **裸整数格位说不出缺席。** `content_bytes`、`clamp_rounds`、`leftover_pct`、两级额度、`shares`（本圈约 10 格）是 int，没有 Basis/Why 可挂。本圈我只能记 0 + 在 `notice_text` 里点名 + 给它们派读者。**这是用文档纪律补格位形状缺口。**
4. **`Says` 三格没有 owner 位。** `Bytes/Kept/SHA256` 全裸，无 Source，所以"我记的是产物字节、不是聊天消息序列化字节"这句归因只能塞进通知块。
5. **`Failure.Kind` 七种取值装不下宿主侧故障。** 复现：截图失败记 `config` → 拒（"config 这一类是按对端响应分的，却没有状态码"）；改 `transport` 才过，但原生码 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE` 只能压在 `fail_detail` 自由文本里。**形状被压成旧读数。**
6. **`declare_reader` 的去重不带 side。** 复现：input 侧 `call` 用读者名 A 声明成功后，output 侧 `call` 再用 A → 拒（"同一个读者声明两遍会把分母数大"）。两侧同名格被迫各用一个读者名——治理成本转给调用方。
7. **预检阶段的红不进汇总。** `tally` 的"被拒的写入 0 次 / 门挡下 0 次"只统计写请求。本圈约 24 次预检拒收在账面上隐形，直接后果见第四节。
8. **机械劳动没有批量件。** 49 格的读者声明要 40+ 次调用，一次一格。本圈这部分是纯开销。

## 三、总结

**它帮的不是"做出来"，是"说出来不许撒谎"。** 本圈它拦下我四处口径错（`reason="stop"`、`model="local-write-tool"`、`Chunks` 默认零值、`config` 无状态码），全是如果不拦就会变成散文的那类。而它对页面像素、配色、文案质量的判别力是 **0**。

**该不该挂：按"这活要不要对外报数"决定，不按活难不难。**
- 该挂：真端点往返、流式分帧、usage 可得、预算裁尾——它的格位在这种负载上才第一次能全亮；以及任何要我对第三方交付"这一圈发生了什么"的场合。
- 不该挂：纯前端/文案/重构这类自己用眼睛和测试就能判的活。今天这种挂法（整圈挂 + 逐格声明）成本是 130 次调用里约 110 次花在记账上。

**最省的姿势（已在第四节实测）：干活时不记账，收口只落 1 发，读者声明只给结论地基那几格。**

**结论一句**：不摘，但降级为"收口件"而不是"常驻件"。它的价值全在可复核性上，而可复核性只有报数时才需要；把它当引擎用会像今天这样，用 4× 的成本买一份对页面质量无用、只对措辞有用的刹车。

## 五、建议清单（给下一个 Agent：按条冷启动可复现，不需要本对话上下文）

读法：每条有 **现象（账上出处）→ 复现 → 改法 → 证红 → 反臂 → 不做什么**。证红=改动生效后必须亮的那一下；反臂=改动**不该**亮的场合。两者缺一的改动不要合，因为按这条仓库自己的规矩，红不了的承诺是散文。

### S1 预检拒收要有一个计数（优先级最高，它已经咬到我）
- 现象：`tally` 报"被拒的写入 0 次 / 门挡下 0 次"，但 `check_call`（预检，一条都不写）被拒 24+ 次在这两栏里全隐形。
- 复现：`kernel.check_call` 传一份 `input.Notice` 整块缺失的载荷 → 被拒；随后 `kernel.tally` 的"被拒的写入"仍是 0。
- 改法：`tally` 加一栏 `precheck_rejected=N`（可再分 类型层/键名层/语义层）。**只进计数，不进哈希链。**
- 证红：连做 10 次故意错的预检 → 该栏报 10；改前它报 0。
- 反臂：10 次全过预检后该栏必须是 0（不许把"检查过 10 次"念成"拒了 10 次"）。
- 不做什么：别把它落成链上条目——那会污染 `RecordCall` 的"写入被拒"语义，也让 append-only 的分母变成两本账。

### S2 给"裸整数=0"一个机械出口，不要急着扩键名表
- 现象：`content_bytes`、`part_totals` 的 Bytes、`clamp_rounds`、`leftover_pct`、两级额度、`shares`、`tool_calls`、`malformed_*`、`says.bytes/kept` 是 int，**结构上说不出缺席**。本圈只能用 `notice_text` 点名 + 派读者声明补。
- 复现：落一发只填 `ContentBytes=0`，`read_back` 回来是 `measured 0`；没有任何一格能说"这个 0 是量到的还是说不出口的"。
- 改法：加一个**只读件**（如 `kernel.zero_int_cells`），报本发/整本账里所有 int 且=0 的格，并明写"int 说不出缺席，此栏不是判定"。比把 10 格升成 Measure 便宜得多。
- 证红（反臂现成，一真一假都在同一本账）：`ai-home-2026-10-18` 第 1 发 `content_bytes=0`（我说不出口 → 假绿，该点名）；第 3 发 `malformed_actions=0`（我整块给了、且整发原子落账才成立 → 真量到的 0）。**分不出这两格的改动，S2 就白做。**
- 不做什么：别默认"int 且 0 就是假绿"——第 3 发那种真 0 会一起被冤枉，那样这栏很快会被无视。
- **同一族的第二个真例（本会话撞出来的，就在本文档里）**：正文曾写"链 391 条"，实为 392——`343+49` 我口算错了，而那句话描述的是**下一发落账之后**才成立的状态，落不进账时它就是假话，**没有任何一格能拦文档里的数字**。修法有两条：每个数后面挂可复算出处（`sha256sum`、`tally` 现值），或写成"以 verify 现值为准"。本文档已改成前者 + 用第 5 发修正，不回头改第 4 发那句错话（append-only 让错留在链上可比，比抹掉诚实）。给 Agent 的硬规矩：**引用账上的数之前先 verify/tally 一次，别把文档里的快照当现值。**

### S3 段名口径先钉死，扩枚举是第二条路
- 现象：`PartCount.Kind` 只认 system/skill/memory/history/toolspec/user；`Kind="content"` 被拒（"content 那一行报了 0 段"）。本地写文件、浏览器验收这类发只能借这套名字 → 6 行 Bytes 全 0，`part_totals` 在这类负载上零信息量。
- 复现：`Order:["content"] + Parts:[{Kind:"content",Bytes:0,Parts:1}]` → 拒；改成 `Kind:"user"` → 过（但说的是假话）。
- 改法：先在 contract 写死一句——**这套段名只描述 LLM 请求形态；非 LLM 形态的发应记缺席，不得借名**。要扩再扩（artifact/browser/fs/tool_result），且扩完必须让借名变得能被点名（回到 S2）。
- 证红：下一个纯工具圈负载照着写，`part_totals` 要么有真字节要么整行缺席，不会出现"6 类共 0 字节"这种既过又无信息量的形状。
- 反臂：真 LLM 往返那一发仍必须能填 6 段真名，改动不许让它退化。

### S4 读者声明：去重带上 side + 一个批量件
- 现象：`declare_reader` 的去重键是 (reader, key)，**不带 side**。两侧同名的 `call` 格共用读者名，第二条被拒："同一个读者声明两遍会把分母数大"。另外 48 格花了 40+ 次调用。
- 复现：`{key:"call",side:"input",reader:"X"}` 成功 → `{key:"call",side:"output",reader:"X"}` 被拒。
- 改法：去重键改成 (reader, key, side)；加 `declare_readers(keys[], side, reader)` 一次声明多格。
- 证红：上面那两条重跑，output 侧第二条该过；一次批量件报"8 格已声明"。
- **必须一并定清的口径**：批量件里第 9 格键名拼错时，是整批拒还是只丢那一格。这条不定，批量件就成了新的静默假绿（今天"未知键不塌成 measured 0"正是靠整发拒收兜的底）。
- 反臂：同一 (reader, key, side) 重复声明仍必须被拒——分母不能数大。

### S5 `Failure.Kind` 缺一个装得下宿主面的桶
- 现象：截图失败记 `config` → 拒（"config 这一类是按对端响应分的，却没有状态码"）；落 `transport` 才过，原生码 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE` 只能压在 `fail_detail` 自由文本里。**形状被压成旧读数。**
- 复现：`Failure.Kind:"config", Status:{Absent:true,…}` → 拒；`Kind:"transport"` → 过。
- 改法：加 `host`（宿主/surface 未就绪，无对端响应、无状态码），或允许 `config` 无状态码但要求 `fail_detail` 带原生码原文。
- 证红：本圈那一发用 `host` 后，`read_back` 的 `fail_kind` 直接说得出"宿主面没就绪"，不再靠 detail 里那串。
- 反臂：真 502/429 仍必须走 `http` 且带 status、`retry_after_ms` 有数或明写缺席——新桶不许变成垃圾桶。

### S6 两本账的"没记"必须是三态之一，不能无声
- 现象：我 3 发全落 wnh@8799；agentkernel@8797 一笔没记。`verify`/`tally` 都不吭声，没有任何件能回答"8797 有没有账"。
- 复现：分别在 8797 与 8799 问 `tally`，两本各报自己的数，没有任何一处指出"另一本没被写过"。
- 改法：汇总里带实例标识（端口/kernel 名），或明写"多实例各记各的、不比对"。无声 ≠ 没有——这正是三态里最容易漏的一态。
- 证红：在 8799 问"8797 有账吗"，它答"没有/不可知"而不是沉默。
- 不做什么：别为这个去开跨实例写锁，先把**说得出**做到。

### 护栏：这四条今天各真拦了我一次，别为了省调用数松它们
三态分离（`Chunks` 三种错法各拦一次）、整发原子拒收（24 次拒收里链始终是 49 的倍数：196→245→294→343）、公式单一 owner（手搭 `ContentCeiling=190000` 被打回并回显公式）、预检与落账同一份判据（实测 2/2，无一次"预检放过而落账拒"）。省调用该省在 S4 那种机械件上，不是省在判据上。

### 成本实测（拿来判断"要不要常驻"）
77（生产+验收+探型，含 26 次预检）→ 25（读者声明+读侧回读）→ **6**（收口一发：写文档 1 + 量字节 1 + 落账 1 + 读回 1 + verify 1 + tally 1，**0 次预检税**）。结论：干活时不挂、收口只落 1 发，是同一份诚实的最省姿势；常驻逐格记账的成本约 4×（本圈 130 次里约 110 次花在记账）。

### 填账形状速查（本圈实测撞出来的，不是照文档抄的）
- `Call` 是**整数发号**，不是名字；一发由 session + 发号 + 侧三轴定身份，重复落同一发会被去重门拦。
- Measure 缺席的正确写法：`Absent=true, Basis=0, N=0`，理由写 **Why**；估算/转述的说明写 **Source**。`Absent=true` 时给 `Basis=5` 会被拒（"没量到的东西说不出是谁算的"）。
- `Basis` 枚举：0 未标 / 1 measured / 2 relayed / 3 estimated / 4 model_says（账本渲染的 5=absent 是落账时由缺席翻译出来的，别手填）。
- `Finish`/`Model`/`WireFormat` 这三对：`said=false` 时串**必须留空**；带值即自相矛盾被拒。
- `Failure`：`Kind` 只认 7 值（空=没故障 / transport / config / http / protocol / malformed_action / budget）；`config`、`http`、`protocol` 这类按对端响应分的，**必须带 status**；无故障时 `Status`/`RetryAfterMs` 走缺席 + 理由。
- `PartCount` = `{Kind, Bytes, Parts}`（`Parts` 是那行的段数）；`Kind` 是闭合枚举，见 S3。
- `Budget`：`ContentCeiling = CallBytesCeiling × (100 − TransportSlackPct) / 100`；`LeftoverPct = 100 − Σshares`；`FixedOverhead` 缺席时 `EffectiveCeiling` 等于 `ContentCeiling`。
- `Cuts` 传空数组即"0 段（裁剪表是空的）"，合法；`Notice` 与 `Failure`/`Finish` **必须整块给**，不给等于让外壳替你补一份零值的账。
- `model_says_sha256` 必须是 64 位十六进制；没有原像就用空串的指纹 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`（这是"量到空"，不是忘填）。
- `declare_reader` 的 key **不带侧前缀**（写 `content_bytes`，不是 `model_input:content_bytes`）；带前缀被当场拒。
- 落账前先 `check_call`，但它与 `record_call` 读同一份判据；收口一发这种重复载荷可以不交预检税（本发实测 0 次）。
- **改动本文件后要再落一发**，别回改旧发（append-only）；旧发的指纹与它当时那份文件内容对应，不是当前内容。
