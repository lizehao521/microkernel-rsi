# 工具提议：五发真调用，三格第一次有非零真数，内核第一次当面拒了我一次

日期：2026-10-13 · 端点：`agnes-3.0-flash`（OpenAI 兼容，带 `tools`）· 驱动：`tasks/mcp/tools_probe.py`
往来全文：`报告/工具提议.txt` · 落盘的账：`报告/样例-工具提议.jsonl`（235 条，每条带原像）
判定：**17 条、0 红**，五发全落账，`✓ 链自洽（共 235 条，其中 235 条比对过原像）`。
key 只在环境变量里，账本全文扫不到 `sk-`。

这一支要的是四样文本端点给不了的东西，四样都拿到了：
`tool_calls` / `malformed_actions` / `malformed_streak` 三格的**非零真数**、
`finish_reason` 的第二种非 stop 形状（`tool_calls`）、
输入侧 `toolspec` 与 `observation` 两个段类第一次被真数填上、
以及**流式里的工具提议到底是怎么分帧的**。

---

## 1. 三件事按顺序发生，第三件是我没预料到的

**第一发**就拿到了 `finish_reason=tool_calls`（出处 `relayed`，是端点自己说的）。
那一发的原话是 **0 字节** —— 模型一个字没说，只递了一个提议：
`{"a": 27, "b": 15}`。这一形状内核是收的（`output_test.go` 里就有一条「原话 0 字节但有 2 个提议，是
function-calling 的正常形状」），落账 47 条通过。

**第二发**把工具结果 `{"sum": 42}` 作为 `role=tool` 的消息喂回去，模型答
「27 加 15 等于 42。」—— 它用的是我给的数，没有自己心算出一个别的什么。
输入侧段表这一发是 `system toolspec user history observation user`，
`toolspec` 与 `observation` 两个段类**从这个仓库建好那天起没被真数填过**，这一轮填上了。

**第三发**是我拿小额度（`max_tokens=6`）去逼一个歪提议。端点回的是 **HTTP 200**，
但 `finish_reason=length`、原话 0 字节、提议 0 个、补全 token 6 个 —— 一个字都没吐就断了。

## 2. 内核第一次当面拒了一次装配，拒的是我

第一次真跑（`报告/工具提议-第一次真跑被拒那发.txt`，账 `样例-工具提议-第一次.jsonl`）里，
我把上面那一发按「正常收尾」装配，内核回的原话是：

```
整发拒收（拒收累计 1 次）：kernel: 输出侧账不自洽，第 3 发整发拒收（输入侧也不写）：
kernel: 这一发什么都没回（原话 0 字节、0 个提议），却记成了正常收尾
```

那一轮的红不是内核坏了，是**它在替我兜一句谎**：`Says.Bytes==0 && ToolCalls==0 && 没故障`
这一形状在账上等于「这一发正常、只是模型懒得说话」，而真相是这一发什么都没做成。
被拒的写入也上了 tally（`被拒的写入 1 次`）—— 拒收不是没发生过。

**改的是调用方，不是判据。** 现在这一发记成：

```
Failure.Kind = "malformed_action"（端点回得通，但那个动作执行不了）
Detail = "端点回了 428 字节、finish='length'、原话 0 字节、0 个提议（补全 token 6）"
RetryAfterMs = 缺席：「原样重发不会变好：同样的额度还会截在同样的地方」
Malformed = 0（一个提议都没有，也就没有「歪的提议」可数）
```

`origin` 那一档也跟着对上：从账上读回来 `fail_kind = measured / malformed_action`（判定 (7)）。

## 3. 真数：歪提议、连歪计数，还有一条因果链

**第四发**（流式）是这一轮最值钱的一发。13 帧、首帧 1210 ms、最大帧间 111 ms，
其中 **8 帧带工具提议的碎片**，碎片拼起来 29 个字符。它吐了**两个**提议：

```
第 1 个：ledger_add {"a": 1234, "b": 5678}   ← 完整，解得出 JSON
第 2 个：ledger_add {"a": 9                  ← 被截在半路，解不出 JSON
finish_reason = length
```

于是按内核文档里那两条判据（没名字 / 参数解不出 JSON），这一发数出
`tool_calls=2`、`malformed=1`、`malformed_streak=1` —— **这三格第一次有真响应上的非零数**，
之前只在单测的合成夹具里出现过。判定 (3) 从账上把 `malformed_actions` 读回来核了出处是 `measured`。

然后是因果链。我第二次真跑时把这条 assistant 消息**原样接进历史**发第五发，对端直接回：

```
HTTP 400  发=1688 收=262
{"error":{"message":"***.BadRequestError: OpenAIException - {"object":"error",
 "message":"Assistant tool call ***.arguments must be valid JSON.","type"...
```

**对端自己不肯收自己上一轮吐出来的东西。** 一个歪提议不只是这一发废了，它会把下一发也带进沟里。
这一轮的 driver 因此改了策略：带歪提议的那条 assistant 消息**整段不带进下一发**，
而「省略」这件事落在**省略它的那一发**（第五发）的裁剪表上 —— 这也是 `Cuts` 与那句知情通知
第一次由真数据填上：

```
第 5 发输入侧：dropped = 1 段：history/第 4 发的 assistant 提议（2 个里 1 个执行不了）
              folded  = 0 段（裁剪表是空的）   clipped = 0 段（裁剪表是空的）
              notice_sent = 是   notice_text = 上一轮模型给出的工具提议里有一个参数不完整，……
              parts 里多了一段 truncation-notice（那句话是真发进请求体的，不是只写在账上）
被省略那条：317 字节，原文指纹 536fafa9345a04c2…（账上带着，第三方能核回被省掉的是哪一段）
```

三档没并成一个总数（判定 (8)），通知确实发出去了且有正文（(8b)），通知本身占一段（(8c)）。
第五发于是正常回来：`stop`、原话 `'4'`、2 个补全 token。

顺带记一笔**我自己的归档失误**：中间那一轮（吃到 400 的那轮）的完整报告被最后一轮覆盖了，
现在只留下第一轮（内核拒收）和最终一轮两份。400 的原文是从当时抓下来的行里引的。

## 4. 三处形状缺陷（不是数值错，是格子不够 / 口径住在错的地方）

**a. 一个 `malformed_action` 档位装了两种成因。**
本轮 `发号 [3, 4]` 都记这一档：第 3 发是**根本没有提议**，第 4 发是**有提议但歪了一个**。
账上把它们分开的只有 `fail_detail` 那句自由文本。内核既不要求 `malformed>0` 才许填这一档，
也不禁止 `malformed=0` 却填它 —— 于是「执行不了」有两句完全不同的话共用一个身份。
要不要加一档取值（比如 `no_action`）或者规定这一档必须带一个原因码，**这条归用户定**，我没动内核。

**b. 提议的内容在账上无处可放。**
输出侧只有三个数：几个、歪几个、连歪几发。判定 (5) 实测：
第 1 发（正常提议）读回来**找不到工具名、也找不到参数原文**；
第 4 发能找到名字 —— 但那是我自己把参数片段抄进 `fail_detail` 的，**参数原文仍然找不到**。
所以第三方拿这本账能知道「这一发有 2 个提议、1 个歪」，
不能知道**是哪个工具、参数是什么**。要复现只能回来问调用方自己的日志。

**c. 「状态码 → 故障类别」的映射住在调用方。**
我第一版把那个 400 记成了 `http`。而内核里 `FailHTTP.RetrySame()=true`、`FailConfig=false` ——
记错的直接后果是：**下一个读账的人会拿一个必然再失败的请求无限重发**。
现在 driver 按类别映射（400/401/403/404/409/422 → `config`，408/425/429/5xx → `http`）。

**这一段原本还写着「这件事今天没有任何判据守着」—— 那句是错的，当天就纠正了。**
判据在，而且是双向的两条（`kind=http ⇒ status≠0`、`kind≠http ⇒ status=0`）；
把它撞出来的是一发**故意写错的 key**：真 401 按 `config` 带码装配被整发拒收，原话
「config 不是 http 那一类，却带着状态码 401」。撞完之后看到的才是真问题——
`FailConfig` 那三种成因在 HTTP 上全都带 4xx，而只有 `http` 那一档许带那个数，
于是**一条真 401 今天没有 honest 的装法**：丢了码记 `config`（那个数只能住进散文），
或者留住码改口记 `http`（把「原样再发有用」写进账，而它没用）——
而后者我在中间那一轮真的走通过，**内核收下了**。
全过程、两层代价（`fail_detail` 的出处还跟着状态码走）和两条修法方向在 `报告/假key一发-401.md`；
README 缺口 10 与 `contract.md` 第四轮已按那个版本改写。

## 5. 历史里丢了说话人：内核留 `role` 那一格的理由，实测对上了

第二次真跑那轮，流式那一发的原话是 `'27 加 15 的和是 42。\n'` —— **它把上一题又答了一遍**，
同时提议去算新题。原因是我那版 driver 只把**问题**接进历史，把模型自己的话丢了。
这不是内核的缺陷，但它正好是内核把 `Role` 单独留一格的理由：
被裁/被带的段一旦丢掉说话人，「模型自己上一轮那句话」就变成「人给的话」，
而这两者的后果正好相反。现在成功的每一发都作为 `assistant` 消息进历史（段类 `history`）。

## 6. 钱花在哪：42% 的入向花在了没做成动作的两发上

```
正常那几发：1308 入 / 55 出
故障与空手的发（第 3、4 发）：947 入 / 70 出
```

内核里那条「这一发的成本能不能进总额」的判据住在 `CostCountable()`（要求 `FailNone` 且真发出去了），
它**不替人累加**。我按它的结论分两栏报，没有把空手那一发悄悄并进正常栏 ——
那等于让一个决定停不停的数有第二个 owner。

## 7. 这一轮仍然没见过的

- `retry_after_ms`：**真端点从没给过 Retry-After**（本轮无 429；上一轮那个 400 也不带）。
  今天唯一带过这个头的还是本地假端点（我自己设的），所以它只证明「读得到就用」。
- `folded` 与 `clipped` 两档：要真的折叠器/裁刀才有数，那是 runloop 的 `ctxbuf`，还没接。
- `budget-exhausted`：要总预算到顶才会出现，driver 没做总预算闸。
- `sent` 三态里的 `SentNothing` 只在预算闸那一支走过（合成数据），真端点上没发生过。
- 非零的 `malformed_streak≥2`（连歪两发）：本轮只连到 1。
