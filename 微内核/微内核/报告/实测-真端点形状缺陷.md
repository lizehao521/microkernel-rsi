# 真端点实测：形状缺陷三条（第 2 号发现带判据建议）

接的不是模型端点，是同机可及的 Deep Research HTTP 服务（`123.56.218.60:18000`），
因为**证据源那个仓库（runloop）不在这台机器上**。这一趟的目的不是"能跑"，
是看字段表换一个真端点之后还剩什么形状不对。

调用方是 `cmd/kresearch`（框架的替身，它 import `net/http`；包内核仍然不联网）。
两发：`POST /api/research/start`（非流式）、`GET /api/research/stream?taskId=…`（流式 SSE）。

## 发现 1：一次真的 GET 被账本说成「一个字节都没发出去」

`OutputMeta.WireBytesOut` 的口径是「**真过网线的请求体字节**」（`output.go` 的字段注释就是这么写的）。
GET 没有请求体 ⇒ 这一格**如实**记 `measured 0`。
但 `Sent()`（同文件 `output.go:136`）拿它当「这一发到底有没有花出去」的**唯一**判据，
于是 `measured 0` → `SentNothing` → 那句渲染成 **「没发出去（数到了，是 0 字节）」**；
再往下 `CostCountable()`（`output.go:151`）因为 `Sent() != SentSomething` 判**假**，
这一发的收字节从此不能进成本核算。

**而这一发真过了网线**：请求行 + `Host` + 一堆头，第 2 发至少上百字节，只是没有体。
所以账本上「没发出去」那句话，对这一发是**假话**。

这一条不是「三态没做到」——三态把「没数到 / 是 0 / 非 0」分得很清，`measured 0` 也确实是我们数的。
它漏的是**另一个方向**：`wire_bytes_out` 这一格的名字承诺「过网线的字节」，
而它实际量的是「请求体字节」。**一个键名装了两个量**，切换条件是「有没有请求体」——
这正是规矩二那个 `bytes_out`（6327 与 11570）的反面同族：当年是两个量共用一个名字被实测抓到，
今天是同一个名字在两种请求形状下指两个量，而且**没有任何一格说出它这次走的是哪一种**。

建议（要判据，不要注释）：

1. 加一格 `header_bytes_out`（或 `wire_bytes_out` 改成「请求行+头+体」的总上线字节，另存 `body_bytes_out`）——
   两个量两个名字，谁都不许再冒充谁。
2. 加一根判据：**`Sent()` 不许从「只有请求体」那一格单独推出来**。
   形状上最省事的写法是让 `Sent()` 需要一个显式的「有无请求体」前提，
   缺前提就拒收 —— 而不是靠注释提醒读的人。
3. 反面的针（慢闸形状）：把 `Sent()` 的判据退回成只看 `WireBytesOut.N`，
   点名的判据必须红。这条针能站住的前提是先有 1，否则「GET 那一发」在测试里根本不存在。

## 发现 2：这一趟量到的两个数，账上压根没有格子放

- **第 1 发首帧 198ms**：非流式那一发的三格必须记 `absent`（判据要求，两头都判，`output.go:264`），
  于是**我们明明量到了首字节等待，却只能写成「这一发结构上没有这一格」**。
  这一条本身是对的（"首帧"是流式的概念），但它暴露了另一半：**没有任何一格装非流式那一发的等待时间**。
- **整发耗时**：第 2 发跑了约 7 分钟（1368 帧、最长静默 16.8 秒），
  这 46 个键名里**没有一个**是「这一发从发出到读完花了多久」。

后果是具体的：这一趟的成本、SLA、超时判定、重试决策全都依赖那个数，
而账上读不出来，框架只能自己再维护一份 —— 于是「一发了多久」这件事实上有了第二个 owner，
而那正是规矩三反例的形状（`Budget` 那次）。

**这一条直接给原文报告 §5 第 4 条（「枚举完备性是单样本假设」）补上了它要的实测反例**：
那份字段表是从 runloop 一份代码逐格挖的，换一个真端点就露出两个量无处落账。
「字段表收全了」从今天起不是未验证的推断，是**已被证伪的推断**。

## 发现 3：94 条里有 50 条在这一趟不携带决策信息（分母，不是结论）

对着 `报告/样例-真接口两发.jsonl` 的 `claim` 逐条分类：

| 类别 | 条数 | 例子 |
|---|---|---|
| 结构性的零 / 否 | 30 | `clamp_rounds` `clipped` `dropped` `cost_countable` `downgrade` `fail_status` `finish_said` |
| 空值（那句「这一格是空的」） | 11 | `endpoint_model` `fail_detail` `fail_kind` `finish` `notice_text` `notice_why` |
| 缺席（没量到，带理由） | 9 | `chunks` `first_byte_ms` `max_gap_ms` `retry_after_ms` `usage_in` `usage_out` |

**这 50 条不能读成「一半格子是废的」**——其中缺席与空值那一半，存在的意义恰恰是
「没发生」与「没量到」必须长得不一样（规矩一）。真要砍，砍的是**另一种**：
`clamp_rounds`、`notice_why`、`leftover_pct` 这类格，**破了以后在两种结论下读数一模一样**，
而它们每一格都要养一根针。这一句正是原文报告 §5 第 3 条的批评，
现在它有了分母，但**"哪些格值得养针"仍然是人的决定**，本件不替你做。

## 发现 4（本轮自己造成的）：闸门唯一能区分「包内核有没有联网」的那个信号，被我加的工具搞浑了

`isolate.go:336` 跑的是 `go list -deps ./...` —— **整个模块**，不是包内核。实测两个数：

```
go list -deps .         = 116 个包，里面没有 net/http
go list -deps ./...     = 208 个包，net/http 在里
kcheck 第 1 节印出来的   = 「依赖闭包 208 个包，越界 0 个」   ← 它说的是整棵树
```

加 `kresearch` 之前这两个数几乎相等（117 vs 116），所以那一栏的 ✓ 事实上就是在说包内核。
**现在不是了。** 后果是具体的一格判据变弱：

> 如果明天有人把 `net/http` 引进 `package kernel`，`Deps` 这一栏**一个数都不会变**（208 里早就有了），
> `越界 0 个` 照样 ✓，而 import 扫描那一栏也会把 `net/http` 归成标准库照样 ✓。
> 也就是说：README 第 6 节「不联网」这一条，**在这一轮之后比上一轮更没人守**了。

这不是"隔离闸本来就看不见三条路"（缺口第 2 条）那一族的重复，而是新的一族：
**边是真的（import 边、闭包边都在），只是被整棵树的平均分摊掉了。**

建议的形状（两条都可判）：

1. `Isolation` 拆两个分母：`DepsSelf`（`go list -deps .`，包内核）与 `DepsTree`（`./...`，整棵树），
   `kcheck` 两个都印；「越界」这条判据**只对 `DepsSelf` 生效**，`DepsTree` 只报分母不做判定
   —— 因为 cmd/ 下面联网本来就是允许的（`kresearch` 就是）。
2. 加一根慢闸针：把 `net/http` 引进 `package kernel` 的某个文件，
   要求「包内核那一栏跳、整棵树那一栏不动」必须被点名接住。
   这根针今天**写不出来**，因为今天只有一个分母 —— 这正是它值得先加的原因。

## 发现 5（顺带）：`kresearch` 自己不是判据

它是**证据**，不是**测试**：跑不绿的时候没有任何东西会红。
`cmd/kcheck` 在 `go test` 下也是 0% 覆盖，同一个道理。
要让它站岗，得先有发现 1 和发现 4 的判据落点，否则接进去的只是一次演示。
