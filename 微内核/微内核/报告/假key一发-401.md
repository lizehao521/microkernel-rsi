# 一把故意写错的 key：`config` 这一档第一次有真形状，顺手炸出一条我写错的缺口

日期：2026-10-13 · 端点：`agnes-3.0-flash` · 驱动：`tasks/mcp/tools_probe.py`（`AGNES_KEY` 换成一串明显的假 key）
往来全文：`报告/假key一发.txt` · 账（临时目录，不覆盖真账）：47 条
判定：**6 条、0 红**，`✓ 链自洽（共 47 条，其中 47 条比对过原像）`，`被拒的写入 0 次`。

为什么花一发去打一个**注定失败**的请求：故障那一族的取值表有七档，
真端点到今天只出现过两档 —— `http`（429/400）与我自己给空手那一发配的 `malformed_action`。
`config`（取值表写的就是「密钥错、模型名不存在、参数非法」）从来没在真往返里落过账，
而它是这一族里最要紧的一档：**它决定下一个读账的人要不要重试**。

## 1. 现场

```
HTTP=401  发出 662 字节 收到 118 字节
对端原话：{"error":{"code":"","message":"无效的令牌 (request id: 20261013...)","type":"AgnesAI_error"}}
```

对端**没有**回 `Retry-After`，也**没有**在错误体里把这把 key 抄回来（我核过账本：`sk-` 一个都没有）。

## 2. 内核拒了，拒的话推翻了我上一轮写进 README 的那条

第一版我按 `kind=config, status=401` 装配，整发被拒：

```
!! 第 1 发被拒：整发拒收（拒收累计 1 次）：kernel: 输出侧账不自洽，第 1 发整发拒收（输入侧也不写）：
   kernel: config 不是 http 那一类，却带着状态码 401
```

**我在大约一小时前把 README 缺口 10 写成「`failure.kind` 与 `failure.status` 今天不互核」，那是错的。**
判据在，而且是双向的两条（`output.go` 的 `Failure.check()`）：

```go
if f.Kind == FailHTTP && f.Status == 0 { … "报了 http 故障却没有状态码" }
if f.Kind != FailHTTP && f.Status != 0 { … "%s 不是 http 那一类，却带着状态码 %d" }
```

注释写的理由是「别处的非 0 状态是把两把尺塞进一格：读的人分不清 429 是对端限流还是我们自己编的号」。
这条**写代码时我读过，但没往「config 也带码」这一层想** —— 因为 go test 的夹具里 `config` 那一发
一直是 `Status=0` 造的。真发一发 401 才看见：夹具替我把取值表里最别扭的一格糊过去了。
README 缺口 10 与 `contract.md` 第四轮都已按实测改写。

## 3. 于是一条真 401 今天没有 honest 的装法

取值表说 `FailConfig` 管「密钥错、模型名不存在、参数非法」，而这三种成因在 HTTP 上**全都带 4xx**；
判据又说只有 `http` 那一档许带那个数。两条之间没有缝：

| 记法 | 得到 | 代价 |
|---|---|---|
| `config` + `status=401` | 类别对、数也在 | **整发拒收**（就是上面那句） |
| `http` + `status=401` | 数留下了 | 类别说谎，而 `FailHTTP.RetrySame()=true` —— 账上写着「原样再发一次有用」，实际只会再吃一次 401 |
| `config` + `status=0`（本轮采用） | 类别对、重试语义对 | **那个 401 没有一格能装** |

中间那一轮（真 400）我走的是第二行 —— 内核收下了，没吭声。
**所以这条互核挡得住「config 带码」，挡不住「把 config 谎报成 http」**：类别那一格是调用方自己填的，
没有第二根轴能反证它。这不是判据太严，是它盯错了方向。

还有第二层：`fail_detail` 的出处**跟着状态码走**（`Status≠0 ⇒ relayed`，否则 `measured`）。
所以走第三行时我不能把对端那句「无效的令牌」抄进 Detail —— 抄进去那一格就被标成「我们量的」，
一句对端的原话读起来像自己的结论，正是它旁边那条判据想防的事换了个方向发生。
本轮因此只写自己构造的判定句，并把码放进那句话里：

```
fail_kind   = config    （measured）
fail_status = 0         （measured）
fail_detail = 本地判定 config：对端回了状态码 401 并拒了这次请求；
              它的原话没有进账（这一档不许带状态码），见调用方日志
retry_after_ms = —（没量到，不是 0）：端点没给 Retry-After，也没说要等多久
```

判定 (10) 是根**示踪弹**：它断言的正是「我们宁可丢数也没有谎报类别」。
哪天判据放宽、开始把码记进 `fail_status`、把对端原话抄进 `fail_detail`，这一条就该红 ——
那时按新口径重写它，而不是让它默默一直绿。

**代价说清楚**：那个 401 现在住在散文里，而「红不了的承诺是散文」是这份 README 的标题级规矩。
要改，方向是两条选一（**都归用户定**）：
① 把互核改成「收到了对端响应的那几类都能带码」（`transport`/`budget` 压根没收到，继续不许），
并让 `fail_detail` 的出处跟着**同一根轴**走（一个口径只许一个 owner）；
② 把「对端回的 HTTP 状态码」做成与 kind 无关的一格，46 键变 47 键。

## 4. 一处差点被我读错的判据，值得留给下一个人

第一版那一轮（唯一一发被拒）里，`账落盘且不带 key` 这条报了红，输出长得像「找到了禁忌串」。
**它不是泄漏**。判定那条函数的语义是「必含项全在 且 禁忌串全不在」，红的报文把两份清单都印出来：

```
RED 账落盘且不带 key | 期望 ['tools'] 去掉 ['sk-this-ke', 'sk-'] 实际：
```

真实原因是那一轮 `账 0 条` —— 空账本里没有 session 名 `tools`，**必含项缺失**；
而 `sk-…` 那串是我列给它「不许出现」的清单，不是命中列表。
修好装配、账上有 47 条之后这一条转绿，我另外逐字节扫了一遍落盘的账：`sk-` 出现 0 次。
顺带一个空账的形状：tally 那一行在 0 条时印成 `账 0 条（）`，括号里是空的 ——
不算错（确实一条都没有），但「（）」读起来像坏了，值得在渲染里交代一句。

## 5. 这一发花掉的东西

一次注定失败的请求（不计费：`usage` 是空的，`CostCountable()` 也因为 `Kind≠FailNone` 把它排除在外）、
一发 `tools/list` 之外的真往返、以及**一次我自己写错并公开的判断**。
后者是这一支最贵也最值的收获：如果我只跑「一切正常」的往返，
`config` 那档永远会按夹具的样子活着，而夹具是我自己搭的 —— 它不会告诉我取值表和判据在打架。

## 6. 补记：同一支 driver 又白要了一发，把 `transport` 那一档也变成了真形状

打一个**没人监听的端口**（`127.0.0.1:9`）就能造出「管路断了」这一类，不花一分钱：

```
HTTP=0  发出 662 字节（真的过了网卡） 收到 0 字节 帧数 0
kind=transport  status=0
fail_detail = 'URLError: <urlopen error [WinError 10061] 由于目标计算机积极拒绝，无法连接。>'（出处 measured）
retry_after_ms = —（没量到，不是 0）    tool_calls = 0（measured，不是缺席）
账 47 条 · ✓ 链自洽 · 被拒的写入 0 次 · 5 条判定 0 红
```

存档：`报告/空端口一发.txt` + `报告/样例-空端口一发.jsonl`。

这一档顺手把上面第 3 节的**分界线**照出来了：**「哪几类能带状态码」和 `RetrySame()` 不是同一条线**。
`transport` 能原样重发（管路断了再发一次确实可能通）却**永远没有**状态码 —— 压根没收到对端响应；
`config` **一定有**状态码却**不许**原样重发。今天那条判据问的是「是不是 `http` 那一类」，
而它该问的是「收到了对端响应吗」—— 这两个问题只在 `http` 那一档上恰好重合过，
所以它一直没被证伪，直到 401 出现。这条区分是给缺口 10 定口径时唯一要钉的东西。

四档故障现在的真形状清点（只算**真往返**落过的，不算夹具）：

| 档 | 真数据 | 出处 |
|---|---|---|
| `transport` | ✓ 连不上空端口 | `fail_detail` 是我们自己构造的 → measured 名副其实 |
| `config` | ✓ 真 401（假 key） | 只能自己造句，对端原话进不了账（见第 3 节） |
| `malformed_action` | ✓ 两种都见过：参数被截、以及空手回来 | 见 `报告/工具提议-实测.md` |
| `http` | **在册的账里没有** | 中间那轮的真 400 按新映射本应归 `config`，而那本账被后一轮覆盖了；真 429 至今只在本地假端点上落过账 |
| `budget` | ✗ 还没造出「总预算到顶」那一发 | 需要 driver 侧的累计闸 |
| `protocol` | ✗ 从没在真端点上撞到过 | |
