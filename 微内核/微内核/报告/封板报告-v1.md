## 2. ①②为什么非改不可：两个独立实例，不是推测

按类别的旧互核（`Kind != http` 就不许有码 / `Kind == http` 就必须有码）挡住了两发真账：

1. **真端点的一发 401**（`config` 类）：对端回了 HTTP，码就在响应里，旧互核要把它归 0，
   于是原话只能住进散文。见 `报告/假key一发-401.md`。
2. **本机假端点的一发 200 坏 body**（`protocol` 类）：HTTP 200 到了、body 解不开。
   照实记 `protocol`+200 被整发拒收（当时整发 47 格全丢），让步记则账上留下
   `fail_status = measured 0` —— 而 HTTP 没有 0 这个码。见 `报告/协议档一发-200坏body.md`。

两发各自独立，都指向同一句：**「是哪一类故障」与「收到过对端响应没有」是两根轴**，
它们只在 `http` 那一档恰好重合。所以新表把「收到过响应」的四档列出来
（`http`/`config`/`protocol`/`malformed_action`），`transport`（管路没通）与
`budget`（我们自己掐的）继续不许带码。范围另加一道：`100..599`，针 m71 守着。

**在册真数的前后对照** —— 这一组数由 `tasks/audit/status_axis_dist.py` 从落盘账上重数，
读数写在 `报告/状态码轴-在册分布.txt`（分堆不靠文件时间，靠内容：账里有 `wire_format`
那一格 = 封板之后落的那本，因为这一格是本轮才进键名表的）：

- **改前那堆**（13 本账、39 发输出侧）：`fail_status` **全是 `measured 0`，无一例外**。
  「没发生」被写成「量到 0」，正是规矩一禁的那一族。
  当年第一次清点时池子只有九本账、27 发 —— 数是会长大的，所以这一条现在交给脚本每次重数。
- **改后那堆**（3 本账、16 发）：`absent 15` + `measured 200 1`。
  那个 `200` 是真从对端响应里量下来的（HTTP 200 + 坏 body 那一发），
  15 个 `absent` 每一个都带着「为什么没有这个数」的句子。
- 这把尺子自己也被种坏输入试过：往改后那堆里塞一格 `measured 0`，
  它印 `STATUS BAD … post_zero_shapes=1` 并以非 0 退出 —— 它不是那种永远说好的工具。
  它的**第一版**反倒演示了反面：把 `(claim, basis)` 拆反了，于是「改前 39 个 measured 0」
  被印成「改前 0 个」，一份读不懂的读数长得像一份好读数；所以现在脚本里硬写着
  `SELFTEST pre-change measured-0 count=%d (must be >0)`，数不到 0 就判 BAD。

## 3. ③的来历：我推翻了自己先前的建议

`报告/待定-两个状态与格式那一格.md` 的草案原本写：「按哪个格式谈」这一格只能记 `measured`，
理由是「对端从没告诉过我们」。响应头/body 探针（`报告/格式自报-流式对照.txt`）查出来
对端在 body 顶层**亲手写了** `object`：非流式 `chat.completion`、流式 `chat.completion.chunk`。
于是那一格有可指名的 Source，该走 `relayed` —— 草案那句话是错的，已按实测改过来。

`relayed` 的代价跟着来：转述不许自己圆场。所以多了 `wire_format_said`（实测「这一发我们
到底知不知道对端自报了什么」）与一道互核：**说知道，就必须真收到过对端响应**
（`output.go:249`）。没收到响应却填了格式，是编造；收到了却不许填 `chat.completion`
以外的猜测 —— 两边各一根针（m72/m73）。

- **我试过的杠杆：把编译串行化（`-p 1`，`KPROBE_LOW_MEM` 默认开）。被测量证伪了。**

### 8b. 探针改成一棵共享树（取材方式，不是判据改动）

`copytree`/`rmtree` 没有上限（`subprocess` 的超时管不到它们），而每根针一棵树在这台机器上
既是速度瓶颈又是卡死来源 —— 第三轮的工作目录里堆了 42 份整树拷贝还删不掉。改成：

- 76 根针**复用同一份拷贝**；每根针前把树按 `SRC` **逐字节**修干净。
  串扰只可能来自「上一根针改的那一个文件」，而它每次都被比对修回。
- 起手自检：刚拷出来时修回必须是 **0**；收尾自检：修回必须是 **1**（最后一根针改的那个）。
  **多于 1 就报「有针改了名单之外的文件」—— 这一轮不算，退出码 1。**
- 汇总里印出取材方式与累计修回文件次，「我以为等价」变成「读数说它等价」。
- 退回老写法：`KPROBE_INPLACE=0`。
- **等价性不靠嘴说**：拿五根已有存档读数的针在共享树模式下重跑 ——
  `m13b`/`m20`（半成品轮：全量共红 1 条）、`m25`（第一轮：RED-WIDER、全量共红 32 条）、
  `m33`/`m80`（修好之后筛针轮：RED-ONLY-NAMED 1）。逐根对不上就不放大轮。
  再加 4 根 kcheck 闸针（第一轮 `GATE-RED 4`）一起验 —— 它们正好是「少拷了 `报告/` 会不会伤到闸门」的探针。

**等价性验过了（17:34，`$TEMP/kprobe-eq-1015-012457-report`）**，九根针逐根与存档读数一致：

```
m13b RED-ONLY-NAMED 1   m20 RED-ONLY-NAMED 1   m25 RED-WIDER 32（宽出点名 30 条）
m33 RED-ONLY-NAMED 1    m80 RED-ONLY-NAMED 1   g1..g4 GATE-RED exit=1
go test 针 5 根：RED-ONLY-NAMED 4、RED-WIDER 1、VACUOUS 0、TEST-BROKE 0、TEST-HANG 0
kcheck  针 4 根：GATE-RED 4、GATE-GREEN 0、GATE-CRASH 0
两类共用：ANCHOR-BAD 0、BUILD-BROKE 0      取材方式：一棵共享树，累计逐字节修回 9 个文件次
共享树起手自检：修回 0 个（该是 0）        收尾自检：修回 1 个（该是 1，就是最后一根针改的那个）
对照 0：PASS 104 / FAIL 0、kcheck 退出 0 —— 成立      对照 T：成立
```

于是"少拷 114 个文件、每根针少跑一趟 `go test`、76 根共用一棵树"这三处改造，
**没有让任何一根针的结论改变**（`m33` 那一格从 `VACUOUS` 变 `RED-ONLY-NAMED` 是我修夹具的既定结果，
不是改造的副作用）。这两条自检（起手 0 / 收尾 1）是"针与针之间不串扰"这件事目前唯一的凭据。

## 10. 封板之后新长的一个面：只读远程审计外壳 `cmd/kaudit`

封板冻的是**内核判据表**（48 键 / 49 格）和它的 76 根针；本节这个外壳**不新增任何格**，
所以它不动那份冻结，也不动 §7a 那份凭据。它之所以存在，是用户问了一句「生成 MCP 服务器的话，
其他电脑能连接吗」之后选定的一句话场景：**远程读那本账做审计**。

### 10a. 它供出去的三件事，和三条边界

```sh
go build -o "%TEMP%\kaudit.exe" ./cmd/kaudit
"%TEMP%\kaudit.exe" -listen 127.0.0.1:8788 -journal 报告/样例-agent.jsonl
```

端点六个：`/healthz`、`/v1/verify`、`/v1/tally`、`/v1/celltable`、`/v1/turns`、`/v1/read_back`。
三条边界都是**判据级**的，不是配置级的：

1. **只读与鉴权各管各的**。任何非 `GET/HEAD` 一律 405，且这个 405 与口令无关。
2. **没口令就查不到账本内容**。401 的响应体里一个字账本都不给（连 `entries` 这种派生数也不给）。
3. **三态不许被压扁**。没有原像的那份账供出去必须是 `undecidable`，既不是 `green` 也不许打 `✓`。

下面这些码和响应体全部出自 `报告/kaudit-实测-1015-094953.txt`（curl 自己印的，未编辑）：

| 请求 | 实测 | 该是 |
|---|---|---|
| `GET /v1/verify`（回环、无口令） | 200，`✓ 链自洽（共 294 条，其中 294 条比对过原像）` | 通 |
| `GET /v1/verify`（网段地址、无口令） | 401，84 B | 拒 |
| `GET /v1/verify`（网段地址、带口令） | 200，135 B | 通 |
| `POST /v1/read_back`（**带**口令） | 405，118 B | 拒（`Allow: GET, HEAD` 那一条由 `TestReadOnly` 钉着，curl 那趟没回头部，不在实测记录里） |
| `POST /v1/read_back`（不带口令） | 405，118 B（**不是 401**） | 拒，且理由与口令无关 |
| `GET /v1/read_back?call=1&side=output`（少 session） | 400，96 B，点名缺的那个轴 | 拒 |
| 供一份 `PayloadOmitted` 的账 | 200，`"state":"undecidable"`、`checked:0`、正文开头是 `—` 不是 `✓` | 第三种答案 |
| 起服务时绑网段又没给口令 | 进程退出码 1，理由印在脸上 | **拒绝启动** |
| 账本被塞进两个字（`"claim":"篡改…"`） | 退出码 1：`第 1 条整格指纹重算不符（某格被改）want=faaa72… got=10cb66…` | **拒绝启动** |

### 10b. 这个外壳自己的一套「能红一次」

`tasks/probe/kaudit_probe.py` 有 **7 根针**，每根抹掉 10a 里的一条承诺。读数（原文归档
`报告/外壳针-7根-1015.txt`，脚本退出码 0，由它自己印）：

```
针数 7（表里 7，本轮实际跑 7）；分类：RED-ONLY-NAMED 7
取材方式：只改 cmd/kaudit/main.go 一个文件，每根针后按原字节修回（累计修回 7 次）
对照 0（干净树全过）：成立；对照 T（认得出测试没跑起来）：成立
```

**它不在 76 根那张表里**，理由写在脚本页眉里：那 76 根是封板内核判据表的针，把外壳塞进去
等于宣布 §7a 那份凭据作废、重跑一轮 1.6 小时。所以外壳有自己的针表和**自己印出来的**分母。

### 10c. 五处被我自己查出来的问题（都是判据/工具瞎掉，不是判据弱）

1. **只读那条判定排在鉴权之后**。第一次跑 `go test ./cmd/kaudit` 就红了，红得对：
   `main_test.go:145: /v1/verify 上 POST 该 405（只读服务没有写入口），实际 401`。
   一个没口令的人探到 401，读到的是「配上口令就能写」——那是这个服务最不该被读出来的意思。
   修法是把方法判定提到 mux 外面（`Allow: GET, HEAD` 一起给），并把测试改成
   **带口令和不带口令都跑一遍**。
2. **`/healthz` 当时根本不查口令**，把 `entries`（账本派生数）白送给任何人。
   这条没有自然红过，是补测时发现的：测试改成六个端点逐个扫之后，它才有判定。
   `checkListen` 同样一条测试都没有 —— 补了 `TestListenGuardRefusesPublicBindWithoutToken`，
   三支都要判（回环放行 / 网段无口令拒 / 网段有口令放行），只判「拒」那一支的话，
   把判据写成「永远拒」也照样绿。
3. **我的对照 T 探测器是瞎的**。第一版只认 `[build failed]`，而 Go 在**测试文件**编译不过时
   印的是 `[setup failed]` —— 于是那一轮 `kaudit_probe` 的对照 T 报「不成立」（退出码 1），
   而 7 根针全红。这不是判据弱，是**探测器认不出「测试压根没跑起来」**，
   而它会伪装成「干净」。修法是两种标记都认，且加一条「没有 PASS/FAIL 判决行」的兜底。
4. **冒烟脚本收不掉自己起的服务**。它拿 bash 的 `$!` 去 `taskkill`，那是 MSYS 的 pid，
   报告里如实印着 `没有找到进程 "1563"`，而脚本以为收了 —— 实际三个 `kaudit-smoke.exe`
   还在监听，其中一个绑在网段地址上。这次是我自己起的、自己发现的，收尾前按 CIM 印出的
   真 PID 收掉了。修法是**按监听套接字的 owner 收**（`netstat` 反查 PID），
   并在脚本末尾加一条 `残留监听数（该 0）` 的自检，收不掉就退出码 5。
   这一条与 §8c 是同一族：**我把机器弄脏了而工具报告说它干净**。
5. 顺带一处会伤到封板轮的：`sync_tree` 只拷 `.go/.mod/.sum`，而 `cmd/kaudit` 的测试读
   `报告/样例-agent.jsonl`。少拷这一个文件，`go test ./...` 会在**探针的临时拷贝**里红，
   76 根的对照 0 当场不成立 —— 红的是探针自己漏拿东西，不是判据弱。
   改成点名把这类数据文件放进取材范围（`EXTRA_DATA_FILES`，只加这一个，不是整份 `报告/`）。
   这是**取材方式的改动**，按 §8b 立的规矩要用存档读数重验，不靠嘴说等价。
   **重验已落地**（10-15 09:58 起跑、10:20 落地，`bash tasks/probe/run_freeze_round.sh eq`，`EQ_EXIT=0`，
   原文归档 `报告/等价性-取材加数据文件-9根-1015.txt`）：九根针逐根与存档分类一致 ——
   `go test 针 5 根：RED-ONLY-NAMED 4、RED-WIDER 1、VACUOUS 0、TEST-BROKE 0、TEST-HANG 0`、
   `kcheck 针 4 根：GATE-RED 4`、`ANCHOR-BAD 0、BUILD-BROKE 0`、共享树起手修回 0、两根对照都成立。
   唯一的差异是**预期内的那一条**：`对照 0` 从 `PASS 104 条` 变成 `PASS 113 条` ——
   多出来的 9 条正是 `cmd/kaudit` 的测试，它们能出现在探针的临时拷贝里，
   就说明这次点名加数据文件加对了（没加的话，那一趟会直接红、整轮当场不成立）。
   反过来说，这也把 §8b 里那句 `PASS 必须是 104 条` 变成了**会腐烂的数**：
   代码里从来没有把它当判据（只判 `npass > 0`），是那句注释在替它说谎 —— 已经改成"条数由它自己印"。

### 10d. 仍未验的一条

从**另一台机器**真的连过来这件事还没做。本机绑网段地址 + 口令 + `curl` 打得通（B 段实测），
但 Windows 防火墙的入站规则我没动过 —— 别人能不能连进来取决于那条规则，不在这里写死。

还有一条**只有散文守着**的：用户立的「`package kernel` 不许 import `net/http`、不许写磁盘」
现在没有任何机器检查在管它。`isolate.go` 把 import 分成 自有 / 三方 / 标准库 / cgo / 怪，
而 `net/http`、`os` 都算**标准库**，所以「0 泄漏」那条判定**抓不到**内核哪天开始联网。
为什么不现在就补进 `cmd/kcheck`：那会改动闸门本身，让 §7a 那份 76 根整轮凭据当场过期，
而封板这一轮的价值恰恰在于「凭据是跑出来的，不是补出来的」。
登在这里、排在 #20 之后作为 v1.1 的第一批，不写成已守护。

## 11. 又一个新面：MCP 的 HTTP 传送（`mcpsrv` + `cmd/mcphttp`），同样不动那份冻结

起因是用户手上那个挂载界面（§10 之后他自己贴过来的配置形状）只给一个 URL 框：
`{ "type": "streamable-http", "url": "…" }`。而我们的 MCP 外壳 `cmd/mcpkernel` 只会 stdio。
两条路：让界面认 stdio（那台机器上没有 `qoderclicn` 可执行文件，界面填绝对路径时先被中文目录名挡了一次），
或者**给同一套协议再加一个 HTTP 传送**。他选了后者，我照做。

### 11a. 先搬家，再加面：协议只能有一个 owner

`cmd/mcpkernel/main.go` 里那 341 行的 JSON-RPC 分发（方法名、10 个工具、每一句回话的措辞）
整块搬到新包 **`mcpsrv/`**，stdio 那一面只剩 46 行读行的循环，HTTP 那一面也不重写一遍话。
理由与 `tasks/mcp/client.py` 头部记的同源：两处各写一遍「我以为服务端长什么样」，
改了一边另一边没改，调用方拿到哪一套取决于它**怎么连上的**，而那个差别从读数上看不出来。

搬家不改行为这件事**不靠我说**：动手前存了两份读数，动手后重跑逐字节比 ——

```
tasks/mcp/drive.py      → MCP DRIVE status=OK checks=27 red=0     （前后 diff 为空）
报告/三分钟接上.txt      → 12 行                                    （前后 diff 为空）
```

### 11b. 新加 Go 测试与能让它们红的针（11 根 → #33 后 13 根 → #35 后 15 根 → #40 后 16 根 → #42 后 18 根 → #41 后 21 根（不绿）→ 重钉后 22 根）

`go test ./mcpsrv ./cmd/mcphttp` 由 `mcphttp_probe.py` 自己印：10-15 那一轮 **PASS 18 条**、
10-16 这一轮 **PASS 20 条**（都不是我从源文件里数出来的；多的两条正是 #33 配的
`TestServerTimeoutsAreSet` 与 `TestQueueTimeoutIs503AndCounted`）。

`s12` 与 `s18` 这两根是**这一轮重钉的**，理由各不同，都得记：

- `s12` 原来钉 `TrySerialize` —— 重构后那个封装**零调用者**（HTTP 面只走 `TrySerializeKind`），
  针咬在死代码上，改它没人报红，21 根那轮读成 `VACUOUS`。死封装已删，针改钉 `TrySerializeKind` 的签名行。
- `s18` 的锚点被自己的重构挪走过**两次**：先是 `s.route(r)` 那两行被合并，重钉成两行锚
  `if out == nil {\n\t\treturn nil, OutcomeNone` 之后，分类那一支收尾时又往这两行**中间插了注释**，
  两行锚当场断成命中 0。所以现在收敛成一条钉法：**只钉那一行会执行的字节**（`return nil, OutcomeNone`，
  全文件唯一），注入体的参数个数还要跟着 `parseErrorReply` 的最终签名写 —— 写错会读成 `BUILD-BROKE`，
  那正好把"针咬不住"伪装成"代码坏了"。**并行节点看不见这个**：写锚的节点数的是它自己那份中间态。

## 12. 稳定性这一支：起跑前的内存闸，和超时针的自动单挑复验（#34）

用户的话是「目前为止还行，要稳定性」。这一支不新增判据、不新增格（仍 48 键 / 49 格、针表仍 78 根），

而那件事当时是靠我**事后手工一根根重跑**才发现的。

**① 起跑前内存闸**（`KPROBE_MIN_FREE_MB`，默认 900 MB）：在动任何文件之前问一次 Windows 要可用物理内存。
拦下的那一次（把阈值抬到机器不可能满足）脚本自己印：

- `NOT_RUN: free 591MB < 999999MB`，退出码 `3`；
- 事后用 python 直接看字节核过：读数文件 `report` **不存在**，说明写在 `report.not-run`（498 字节、5 行、UTF-8 可解码）。

放行那一次也在报告头上留下一行可追溯的判断，不隐藏：
`起跑前内存闸：可用 647 MB（阈值 550 MB）—— 放行`。
**代价说清**：这台 4 GB 的箱子在会话里空闲只有 ~600–740 MB，默认 900 今天是**拦得住**的，
所以本轮和下面那份整轮都是明确压低阈值跑的，那行「放行」就是「在拥挤机器上跑的」这个标记。
但同一个数在不同时刻差得远：整轮 03:28 起跑那次印的是 `可用 1055 MB` —— 那个值**连默认 900 都过**，
所以"压低阈值"在那一轮上其实什么都没改变，它改变的是白天会话期那 600–740 MB 的时刻。

**② 超时针自动单挑复验**：落针那一段从主循环抽成 `probe_one()`（复验必须拿同一份规则跑第二次，
两份写法一定会分叉），第一趟超时的针自动单挑再验一次，按复验结论改写那一行：
接得住 → `RED-ONLY-NAMED 1 / 单根复验`，该轮 `空针/坏针 0`、退出码 0；
接不住 → `复验仍超时 —— 这不是机器的账`，留在超时档、参与「这一轮不绿」。
两支都是**逼出来**的（拿脚本的 Temp 副本注入「第一趟一律记成超时」；那个开关不在仓库的脚本里；
再把 `KPROBE_TIMEOUT` 压到 5 秒让复验也真超时，那一次连 `对照 0` 都被掐死，所以退出码是 2 不是 1 ——
正是「对照不成立 ⇒ 读数不可信」那条在起作用）。原始读数：`报告/稳定性-内存闸-拦下与放行-1016.txt`。
