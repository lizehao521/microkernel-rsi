## 二、#20 现在有四个种植样本：`check_call` 正文说拒、标志位说没错

| 种的坏法 | `check_call`（正文 / isError） | `record_call`（正文 / isError） |
|---|---|---|
| `ContentBytes=999999` 超各段相加 | 「各类段相加是 20 字节，而内容总字节记的是 999999 —— 两个数各算了一遍，至少一个是错」**/ False** | 同一句理由，整发拒收 / **True** |
| `Call="第一发"`（类型错） | 「第几发是 0，发号从 1 起（0 会被读成「还没发」）」**/ False** | 同一句 / **True** |
| 整个 `input` 键不给 | 同上「第几发是 0…」**/ False** | 同一句 / **True** |
| `Tokens` 拼成 `Tokenz` | 「token 数 有数 0 却没说谁算的（basis 空）—— 这一格会被下游当成实测」**/ False** | 同一句 / **True** |

一个只读 `isError` 的调用方，拿到的是**四次"通过"**。而它拿到的正文里其实写着拒 —— 于是
"拒了"这件事完全取决于调用方有没有去解析一句给人看的话。

## 三、最坏的一条：**「整块漏填」被补成零值，还被记成 `measured`**

发号 9：`input` 里**根本没有 `Notice` 这个键**（不是给它空值，是这个键没出现）。

    check_call  isError=False：输入侧：自洽 / 输出侧：自洽
    record_call isError=False：整发落账 49 条 … 链上共 147 条
    read_back(第 9 发 input) 里那四格：
        notice_sent      measured  否
        notice_trimmed   measured  否
        notice_why       measured  （这一格是空的）
        notice_text      measured  （这一格是空的）

发号 10 是**对照**：调用方老老实实给了 `Notice{Sent:false,Trimmed:false,Why:"没折叠没裁尾"}`：

        notice_why       measured  没折叠没裁尾        ← 唯一差别

也就是说：**"没人告诉我们有没有发通知"和"我们量到它没发通知"，在这本账上是同一个形状，
而且两格都盖着 `measured`。** 内核自己的口径是三态：缺席不许塌成 0、忘了填不等于缺席
（`Absent` 那一档存在的唯一理由），外壳却在门口把它塌回了零值并署上"实测"。

缓和一点的事实（也得记）：读回时那两格印的是「（这一格是空的）」，肉眼看得见不对；
但 `Basis` 那一栏写的是 `measured` —— 任何**按键名扫账本**的分析层读的是档，不是那句人读补充。

## 四、顺带挖到一条传输层的（B 报的"空回话"就是它）

`arguments` 是一段坏 JSON 时：

    HTTP 状态：202   Content-Length:0   正文长度：0 字节

202 在这一面是"通知，没有回话"的合法响应 —— 于是**一个解不开的请求体被当成通知打发了**：
调用方拿不到任何理由，而且这次失败**不进拒收计数**（收尾 tally：`被拒的写入 7 次` = 我那 7 次真拒收，
坏 JSON 那两次不在里面）。同一面在整条请求体都不是 JSON-RPC 时是老实的：

    HTTP 400  正文 {"error":"体不是一条 JSON-RPC 请求（要有 method）","got_bytes":12}

所以"塌成没回话"是**分叉里只补了一条**：认不出请求 ⇒ 400 有理由；认得出请求、认不出参数 ⇒ 202 空。

（10-16 晚补：剩下那条分叉也补上了，而且**这一族的第四种形状**是被针照出来的，不是我读代码读出来的 ——
`{"jsonrpc":"2.0","method":""}`（有 `method` 键、值是空串 ⇒ 过了门）过去被我错判成"通知"、安静拿 202，
现在回 `400 + -32600`，凭据在 `报告/已落地-解不开的请求不再塌成202.txt` 文末那一节。
补它时又查明一件事：**门自己拒掉的那一类**（连 `"method"` 键都没有的体）虽然回了 400 和理由，
却**不进任何计数** —— 既不在 `doorRefused` 也不在 `badRequests`。"被拒也要看得见"这条原则在第四个桶上还没落实，
已单独立成看板 #44。）

## 六、立案（不在这份里修，按老规矩一件一件来）

- **#41** 参数解不开塌成 202 空回话：要当场点名"哪一段解不开"，并让它进拒收计数。
- **#42** 外壳把缺键补成零值、内核把这些格署成 `measured`：解不开/没给要**结构化地报**，
  或由外壳把"整块没给"传成 `Absent` 而不是零值 —— 这一条动了"忘了填 ≠ 缺席"那条口径的门面，
  属于外壳不判据：判据表一个字不用动（`Absent` 档本来就在）。
- **#20** 本轮拿到四个种植样本 + 表格，修法不变（命名解码错误 + 预检走同一份 `RecordCall` 的临时副本 + 结构化 verdict）。
