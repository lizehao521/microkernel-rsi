# 第一支 Agent：回边接上了，但接的是装饰 —— 以及内核第一次拒一个新写的调用方

日期：2026-10-13 · 新脚本 `tasks/mcp/agent.py`（约 250 行，纯调用方，**没动内核一行 Go**）
· 真跑端点 `agnes-3.0-flash` 4 发 · 自检走本机假端点（不花钱）

## 0. 为什么造这一支

前面量到一条：两个真跑驱动里 `read_back`/`tally` **全在回合循环之后**（`tools_probe.py` 循环 `:356` vs 读侧 `:460`），
所以内核只矫正写账的人，不矫正模型的下一步。用户说"先造一个 Agent 试试" ——
这一支的目的不是做一个能干活的 Agent，是**把那条回边真的接上一次，看它是不是实的**。

## 1. 造的是什么

一个循环（不是脚本化的五发）：给一道必须分几步用工具才算得完的题
（`27+15+8+34`，答案 84，可机器核对），模型每发自己决定"提议加法"还是"给结论"，
Agent 执行工具、把结果作为 `observation` 段发回去。每发都：先 `record_call` 落账，
再 `read_back` 读回格值，由一张 `POLICY` 表决定下一步（重发 / 等一等 / 停 / 挤历史 / 执行工具 / 收工）。
每条决定都记 `依据=哪一格 / 值 / 动作`，轮末吐一个数：**账本触发过几次决定**。

## 2. 最值钱的一条：内核第一次当面拒了一个**新写的**调用方

自检那一趟，第 1 发就被拒：

```
kernel: 入 token 那一格的出处是 measured —— 分词器在对端，我们只能转述（或如实记缺席）
```

是我在 `agent.py` 里把 `UsageIn` 标成了 `MEAS`（应该是 `RELAY`）。这条之所以重要：
`agent.py` 是从零写的第二个调用方，**它没背过 README 的任何一条判据**，
第一次交账就被同一道门口拦下。所以"转闸只对我熟记的规则生效"这个怀疑被否掉了 ——
它对陌生调用方也生效。当场按规矩改了调用方，没有放宽判据。

（本 session 这类拒收累计 3 次：200 空响应记成正常收尾、`protocol` 带状态码 200、这一次的新调用方标错出处。）


任务真做完了（最终回答里出现 84），四发 `content_bytes` 571→784→996→1209 逐发长，
链自洽，账本字节里扫不到密钥（前 10 字符与 `sk-` 都查）。

## 4. 但是：`from_ledger=4` 这个数字是假的，我自己戳破它

四条"依据账上"的决定长这样：

```
第1 发  依据=tool_calls（账上的数）  值=('measured','1')  动作=执行工具并把结果作为 observation 发回去
第4 发  依据=finish_reason          值='stop'            动作=收工
```

**我是先从本地 `t["calls"]` 做完了"执行工具"这个决定，再去读那一格来标注的。**
数一致是因为它俩同源 —— 那一格就是我上一行填进去的。
判定 `(C)` 判的是我自己写的标签，等于**自证**；这正是本项目最恨的那一族
（「不许有一格在两种结论下都 +1」——`kernel.go` 不变量第 3 条）。

所以这一支证明的是：**回边可以接得一个字节都不改变行为**。接上 ≠ 有用。

## 6. 下一支要测什么（这一支没测到的那个数）

要让"账本触发决定"不再是自证，只有一个办法：**造一个只有账本能答、本地信息答不出的决定**。
现成的就是续跑 —— 新进程只带落盘那本账（`load_journal`），不带着内存里的 `MSGS`，
让它照着账决定下一发发什么。预期这一支会**分裂成两种结果**，而那正是数：

- 计数量出来的决定**能**只靠账：`fail_kind`（该不该重发）、`malformed_streak`、被拒计数、
  `content_bytes`（要不要挤历史）—— 这些每发都在链上。
- 内容类的决定**不能**只靠账：账上只有 `content_bytes=571` 和 `model_says_*` 的**数与指纹**，
  没有原文（缺口 12 已定性：这本账是审计件，不是恢复件）。
  所以"下一问该问什么"只能靠框架自己另存的原文 —— 那一刻就当场测出**缺口 12 是真挡路还是纸挡路**。

这个数是**分支点**，不是形容词：跑出来"计数类 4/4 能、内容类 0/3 能"，
就说明要不要新开一格装原文，得由这个数决定，而不是由我或 anybody 的立场决定。
