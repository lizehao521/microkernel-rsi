# 走私测试：改了模型说过的那句话，47 格里没有一格有反应

> **先读这一句：这件事真实发生过 0 次。** 下面那个"改了"是我自己按一个旋钮改的
> （`SMUGGLE=1`），不是任何一端自然发生的故障。所以本报告的结论只到"**这个能力内核没有**"为止，
> **不构成改造依据** —— 给零观测实例的类别新开一格、新加一道拒收，正是这份 README 一直在防的过度建设。
> 真会发生的那一族只有一条非人造路径：额度挤不下时对 `history` 段做 `tail-dropped`
> （`input.go` 的 `MayShrink` 明确允许），挤完发出去的就不是账上指纹那句 —— 那一条**本报告没跑**，
> 所以它现在同样是假设。判生死只需要一次"额度小到必须挤历史"的真往来：两把指纹对上就关掉这条。

日期：2026-10-13 · 端点：**本机假端点，不花钱**（`tasks/probe/fakellm.py`）· 驱动：`tasks/mcp/tools_probe.py`（`SMUGGLE=1`）
本轮**没动内核一行 Go、没动任何判据文件**，加的是一条判定（`(11)`）和一个旋钮。

## 0. 这一支要量的东西（是"有没有"，不是"好不好"）

用户提的定位是：这枚内核下一步可能是 **AI 应用 / Agent 的警卫员**。
"转闸"和"警卫员"的分界在这里能说成一句可测的话：

> 账上已经有第 N 发**模型原话的指纹**（`model_says_sha256`），
> 第 N+1 发又把这句话当作历史**真发出去了** —— 有没有任何东西比对这两者？

原料两边都在账上，所以这不是"要不要新增一格"的问题，是"有没有那段检查代码"的问题。
能测，就测。

## 1. 怎么走私

第 2 发模型真回的那句是 `和是 42。`。装配第 3 发的历史时，把这句改成 `和是 43。` 再发出去，
而**第 2 发的账照实记**（`Says` 那格仍是真话的字节数与指纹）—— 这正是代理之间最常见的错：
把上游的话转述给下游时改了一个字，而下游看不出来。

两臂各跑一遍完整五发，假端点每次**重启**（它的 429 计数器是全局的，不重启第二臂会在第 2 发被截断 —— 这是我第一版的无效结果，已重跑）。

| 臂 | 结果 | `(11)` 那条判定 |
|---|---|---|
| 对照（不改） | `status=OK checks=20 red=0 turns=5` | **PASS**：账上 `addd5ed1ab17…` == 发出去的 `addd5ed1ab17…` |
| 走私（改一个字） | `status=RED checks=20 red=1 turns=5` | **FAIL**：账上 `addd5ed1ab17…`，发出去的是 `e6397ea0187b…`（内容 `'和是 43。'`） |

## 2. 关键的数：内核**收下了**那一发，而且链自洽

`报告/走私测试-改了那句.txt`：

```
账 235 条（absent=17 estimated=5 measured=188 model_says=5 relayed=20）；被拒的写入 0 次
✓ 链自洽（共 235 条，其中 235 条比对过原像）
PASS  第 1 发落账通过 / 第 2 发落账通过 / 第 3 发落账通过 …（五发全过）
```

也就是说：改过的那句进了第 3 发的历史、整发装配被**接受**、哈希链**自洽**、拒收计数**为 0**。
内核那两道牙（整发拒收 + 链）对这件事**全绿通过**。唯一发现它的是我新写的那条判定 ——
比对是**我在驱动里做的**，不是内核做的。

## 3. 最扎心的一个数：改动在账上是**隐形的**

把两本 235 条的账逐格对齐（`(step, kind) → claim` 全量比），
取值不同的格**一共 1 格**：

```
step=4  model_output:first_byte_ms : '1' -> '2'
```

—— 那是首帧等待的**毫秒噪声**，跟走私无关。

`和是 42。` 改成 `和是 43。` 是等长的，所以连 `content_bytes`、`wire_bytes_out`（1108）
这些字节格都没动。**换句话说：47 格里没有任何一格因为这句话被改而变过。**
"缺席 ≠ 0"那套逐格出处的功夫做得再细，管的都是"这一发自己填的数自不自洽"；
跨发的那句"下游拿到的历史，是不是上游真说过的"，今天不在任何一格里。

## 4. 这对"警卫员"那个读法说什么

不是"做不到"，是**差一段比对代码 + 一处口径**，而且原料齐了：

| 警卫员要的动作 | 现状 | 证据 |
|---|---|---|
| 存住"上游真说过什么" | **有** | 第 N 发 `model_says_sha256`（本轮实测两臂都对得上原话） |
| 存住"下游真发出去什么" | **有** | 第 N+1 发输入侧 `Parts`/`ContentBytes` 与 `history` 段（`tools_probe.py` 的 `SEGS` 与账同源） |
| 比对两者并在不符时拒收 | **没有** | 本轮 `(11)` 红，而内核 `record_call` 接受、链自洽 |
| 拒收时把不符说清是哪一段 | **没有格** | `Cut` 有 `SHA256`（裁剪留痕用），但没有"这段历史对应第几发原话"的引用键 |

第四行是真正的设计缺口，不是补一段代码就完事：要比对，就得让输入侧的 `history` 段
带上"它指第几发"的可核引用 —— 而这件事落在**缺口 11（工具提议的名字与参数无处可放）那一族**，
而那一族已经定了"缓到接 runloop 一起定"。所以这支的结论**不给新格**，只把"缺哪段代码"钉成实测。

顺带纠正我自己一句话：README §2.4 那句「没有死格，只有还没接的端点」本轮又被收窄一次 ——
这一支证明**格全活着、也全被填对了，仍然拦不住一句话被改**。格子准 ≠ 内容真。
