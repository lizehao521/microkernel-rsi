# 慢闸 62 针 · 挂载轮结论（含两根锚点漂了的针）

日期：2026-10-13 · 原始汇总：`报告/慢闸62针-挂载轮.txt` · 作废的那一半：`报告/慢闸62针-挂载轮-被误杀半途.txt`
**后续：同一天补跑了一次整轮 64 针（`报告/慢闸64针-补针后整轮.txt`，退出码 0，全绿）—— 那份是现在的分母，见第 6 节。**

这一轮是「把内核挂成 MCP 服务」之后重跑的，目的有两个：新针 `j10` 要能咬住，
以及**这一轮之后本轮所有结论才算有闸兜着**（`record.go` 是判定文件，改它必须配针）。

## 1. 它自己印的数

```
针数 62（go test 58 + kcheck 4）
只有点名的红 45；红得更宽 11；闸门报红 4
空针/坏针 2 —— m59-AbsentKeys不只挑absent档、m60-CellsOf不按发与侧过滤（都是 ANCHOR-BAD）
VACUOUS 0、TEST-BROKE 0、BUILD-BROKE 0、GATE-GREEN 0、GATE-CRASH 0

—— 两根对照 ——
对照 0（干净拷贝）：go test 退出码 0、PASS 100 条、FAIL 0 条；kcheck 退出码 0  ->  成立
对照 T（探针认得出「测试没跑起来」）：成立
```

对照都成立，所以那 2 根坏针说的是**探针自己**，不是判据弱，也不是树坏。

## 2. 新针 `j10` 咬住了

```
== j10-读侧丢了session这一轴
   点名该红：TestCellsOfKeepsTwoSessionsApart
   实际报红：TestCellsOfKeepsTwoSessionsApart
   没红的点名：无
   全量共红 1 条: TestCellsOfKeepsTwoSessionsApart
```

把 `CellsOf` 的 `e.Session != session` 那一轴拆掉，只有点名的那一条测试红 ——
不是「顺带挂了一片」，也没有「拆了没人吭声」。这一根针是从**挂载实测**撞出来的
（两个 session 各记一次第 1 发，读侧回「共 40 格」），一个 session 的测试压根撞不到它。

## 3. 这两根针为什么坏：改判定文件的代码，锚点会漂

```
!! m59-AbsentKeys不只挑absent档: 锚点命中 0 处（该是 1 处）->
   '\tfor _, c := range CellsOf(docs, step, kind) {\n\t\tif c.Basis == BasisAb'
!! m60-CellsOf不按发与侧过滤: 锚点命中 0 处（该是 1 处）->
   '\t\tif e.Step != step || !strings.HasPrefix(e.Kind, prefix) {'
```

两根针的锚点写的是**加轴之前**的那几行。上一轮我给读侧三个入口补 `session` 参数，
行文本变了，针就找不到该弄坏的地方 —— 于是 `m59`（AbsentKeys 只挑 absent 档）与
`m60`（CellsOf 按发号与侧过滤）这两处破坏**本轮没有任何针覆盖**。
注意 `j10` 不顶替它们：`j10` 拆的是 session 那一轴，`m60` 拆的是发号与前缀，两个是不同缺陷。

这就是「针与代码住在同一个仓库、必须一起改」那句注释的实价，这次是真撞上了：

- `m59` 的锚点补上 `session` 形参；
- `m60` 的锚点换成带三轴的那一行，破坏只拆「发号 + 前缀」两轴（session 留给 `j10`，两根不许重叠）；
- 修完不需要重跑 62 根（每根一趟全量 `go test`），所以给探针加了一个**可选的第 5 个参数**
  做针名过滤器。筛过的轮子在报告头上明写「不算整轮结论」，末尾的「针数」也不再是整轮分母 ——
  过滤器省的是时间，不许它顺手把结论的分母也改了。

重跑见 `报告/慢闸-锚点修复-筛针轮.txt`，**只跑这两根**（退出码 0、两根对照成立）：

```
m59-AbsentKeys不只挑absent档        RED-ONLY-NAMED 1   （只有点名的 TestAbsentCellsLandOnTheLedgerAsAbsentNotZero 红）
m60-CellsOf不按发与侧过滤            RED-WIDER      2   （点名的 TestCellsOfReadsBackOneCallOneSideOnly 红了，
                                                        另带 TestCellsOfKeepsTwoSessionsApart —— 拆掉发号与前缀两轴之后，
                                                        只看 session 也拦不住串发，两条测试都该同时红）
ANCHOR-BAD 0、VACUOUS 0
```

那一行「跳过 60 根（表里共 62 根）—— 上面那个「针数」不是整轮的分母」是筛过的轮子必须带上的一句话：
它只够回答「这两根针的锚点修好了没有」，**不能当整轮结论用**；整轮结论仍然是上面第 1 节那份。

## 4. 顺带看清的一件事：十一根针「红得更宽」

`m25`（两个字节量又共用一个键名）一处破坏打挂 **29** 条测试，`m45` 24 条，`m29` 9 条。
这不是坏事 —— 一根破坏能波及多远，量的是那张判据被多少条测试**间接**依赖。
但它是信号：这三处一旦真要改判据（比如把 `tokens` 与 `usage_in` 钉成相等），
红的会是一大片，而不是一条安静的点名。改之前该先看这三行。

## 5. 本轮之后重跑的快闸

```
go vet ./...            无输出
go test -count=1 ./...  ok  agentkernel
go run ./cmd/kcheck     退出码 0、✗ 0 行（读侧那一条现在也带上了「另一本账不许混进来」）
tasks/audit/celltable_audit.py  status=OK keys=46 cells=47 drift=0
```

`kcheck` 6.5 那条文案原本写着「CellsOf 按 <kind>: 前缀与 step 过滤」，那是一句**过期话**
（读侧现在是三个轴）。现在它不光改了话：闸门里多 Append 了一条**同发号、同侧、同键名、
不同 session**的条目，并断言两本互不混入 —— 快闸第一次也守这根轴，而不只是单元测试守。

## 6. 补针：假 key 那一条撞出的判据，原来「有测试、没有针」（表从 62 根变 64 根）

一发故意的假 key（见 `报告/假key一发-401.md`）撞出 `kind`↔`status` 那条**双向互核**一直在那儿，
而它当天还写进了 README 又被我纠正 —— 顺着去看针表，发现这两条判据**有测试、没有针**：
没人证明拆掉它们测试会红。补上 `m69`（任何类别都许带状态码）与 `m70`（http 不带状态码也放行），
筛针轮重跑（`报告/慢闸-新针m69m70.txt`，退出码 0、两根对照成立）：

```
m69-任何类别都许带状态码    RED-ONLY-NAMED 1   → 只有 TestFailureNeedsADetailAndOnlyHTTPCarriesAStatus 红
m70-http不带状态码也放行    RED-ONLY-NAMED 1   → 同上那一条
ANCHOR-BAD 0、VACUOUS 0、BUILD-BROKE 0
```

两句要说在前面：

1. ~~**64 根没有跑过一整轮。**~~ **这句话已经被推翻了**：随后跑了整轮 64 针
   （`报告/慢闸64针-补针后整轮.txt`，退出码 0）——
   `go test` 针 60 根：RED-ONLY-NAMED 48、RED-WIDER 12、VACUOUS 0、TEST-BROKE 0；
   `kcheck` 针 4 根：GATE-RED 4、GATE-GREEN 0、GATE-CRASH 0；ANCHOR-BAD 0、BUILD-BROKE 0；两根对照都成立。
   **这一份才是本轮所有结论的分母**，上面第 1 节那份（62 针）是它的前身。
2. 那份新针报告头上印的那句「只够回答这两根针的锚点修好了没有」是**旧措辞**：
   进程带着它启动，我随后把脚本改成通用的一句（「筛出来的这几根针咬不咬得住」）。
   报告是当时那一份的原文，不改写历史产物 —— 整轮那份里这一行已经不存在了（没筛针）。

## 7. 一句诚实的话

这一轮跑到一半被我误杀过一次（用 `taskkill /IM python.exe` 停本地假端点，
把 40 分钟的针进程一起杀了，PID 9324）。那份半途报告留在盘上并标了作废，
本文说的是重启后跑完的那一份。**操作失误不是探针变红**，也不许把它写成「跑过了」。
