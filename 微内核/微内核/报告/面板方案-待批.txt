# 面板方案（待你圈批，未开工）

日期：2026-10-15 · 前置：等 78 根整轮落地（#28）之后再动手；面板不新增内核文件，不额外要求重跑那 78 根。

## 0. 它是什么，以及它明确不是什么

**是**：`kaudit`（只读那面）的六条端点的**一块表**，专门显示只有我们会显示的东西——
每一格的**出身**、被拒的写入**指名到哪一条判据**、链的**三态**（自洽 / 不符 / 核不了）。
**不是**：trace 瀑布、prompt 全文检索、排行榜。
这条界线是 10-15 调研给的：授权闸门那一层已经挤满（微软 AGT、Google Agent Gateway、RSA、NVIDIA OpenShell、Snowflake），
观测那一层是 OTel GenAI 的事实标准（Langfuse/Phoenix/Datadog）；**面板若长成第三家观测工具，就是必输的那条路**。

## 1. 数据源（不动内核）

- 只走 `cmd/kaudit` 的只读端点：`/healthz`、`/v1/verify`、`/v1/tally`、`/v1/celltable`、`/v1/turns`、`/v1/read_back`。
  这六条今天都有读数可指（`报告/kaudit-实测-1015-094953.txt`：GET 200、POST 一律 405、无口令 401 且响应体不含账本内容）。
- **不接 `cmd/mcphttp`**——那面有写入口（`record_call`/`load_journal`）。面板上出现任何"改账"的按钮，
  只读这件事就废了；这条不需要测试来证明，靠的是**它连不上**（不接、不在同一端口）。
- token 只从环境变量读，绝不写进文件、绝不进账本；面板自己**不持有任何凭据**。

## 2. 首屏四块（每块都挂一条能失败的判分线）

| 块 | 显示什么 | 判分线（可当场验，不是"看着顺眼"） |
|---|---|---|
| ① 结论条（最顶，不许折叠） | 链的三态一句话 + `被拒的写入 N 次` | 空账必须显示 `— 尚无账可核（共 0 条）`，**不许出现绿色/✓**（这条判据今天刚落地：`已落地-空链不许打勾.txt`）；被拒次数与 `tally` 原话逐字一致 |
| ② 出身分布 | 五档 basis 横条，`absent` **单独一列**且带"缺席 ≠ 0"的字样 | 拿 `样例-toolface-1015.jsonl`（已知 `absent=5 estimated=2 measured=37 model_says=1 relayed=4`）比对，六个数一个都不许错 |
| ③ 一发解剖 | 三轴（session / 发号 / 侧）→ 逐格：键名、人话、basis、source、指纹 | 少给任一个轴时，页面必须显示 400 的那句**点名缺哪个轴**，不许退化成空白列表（`报告/kaudit-实测-1015-094953.txt` 里有这条原话） |
| ④ 对质台 | 输入一条格的指纹 → 回答"第三方能否从 payload 重算出它"，三答案：可重算 / 对不上 / **没有原像所以不可判** | 喂一份 `PayloadOmitted` 的账：这一列必须整列灰，**不许出现"全绿"**；今天这条已有针（`t6-核不了压成绿`），面板是它的第二处显示 |

## 3. 禁区（写进方案，防我自己以后手滑）

1. 不做时间线/瀑布图——那是 OTel 那一层已经做好的事。
2. 默认**不显示 payload 原文**。这本账最值钱也最危险的就是原话；要看原文得点一次"我要看原文"，
   并且页面顶部留一行字："此操作不写日志，因为这一面根本没有写入口"。
3. 不做分数、排行、通过率。一旦有分数，别人就会拿答题来考内核——8 题盲测已经演示过这种错位。
4. 不静默重试、不缓存旧读数（缓存会把"这一秒链不符"洗成"看起来一直绿"）。
5. 链不符/载入被拒时，页面必须把**拒绝原话**原样印出来（例如
   `第 1 条整格指纹重算不符（某格被改）want=faaa72… got=10cb66…`），不许翻译成"加载失败"。

## 4. 技术形态与代价（这台机器只有 4 GB）

- **单文件 HTML + 原生 JS**，无构建链、不装 npm 包（也符合你"未经同意不装东西"的规矩）。
- 位置：`面板/kaudit-panel.html`（跟着仓库走，纯文本，可 diff）。
- 打开方式：浏览器开本地文件，XHR 指向 `http://127.0.0.1:8798`（`kaudit` 需先起，只绑回环）。
- 一个已知摩擦：本地文件跨源请求可能被浏览器 CORS 挡。两条解法，都不动内核——
  (a) 让 `kaudit` 加**一个响应头** `Access-Control-Allow-Origin: 127.0.0.1` 的受限回显；
  (b) 面板直接由 `kaudit` 自己在 `/` 上吐这一个 HTML 文件（少一个源，也少一层 CORS）。
  我倾向 **(b)**：`kaudit` 已经是只读 HTTP 服务，让它顺手把这张表交出去，
  比新开一个静态服务器少一个可写面。**这一步会动 `cmd/kaudit`，所以它自己的 8 根针要加到 9 根**（新针：`/` 不许成为写入口、CORS 只放只读方法）。

## 5. 里程碑（每个都能当场验）

- **M0**（半天）：①+②，配第一根针（空账不许绿）。
- **M1**（半天）：③，配第二根针（少轴退化成空白就红）。
- **M2**（一天）：④对质台 + (b) 路线接进 `kaudit`，配第三根针（`PayloadOmitted` 整列必须灰）。
- **M3**（待你点头才排）：`gen_ai.*` 映射表的**显示层**（映射表本身是 v1.1 的活，不属于面板）。

## 6. 顺手能被面板解决的一条指标缺口

调研里那句"哪些调用被拒、为什么、**以及被拒之后 agent 怎么改**"——我们只有前两项。
面板可以立刻显示：同一个 session 里相邻两次落账之间的**序号/时间差 + 前一发的拒收原话**，
读起来就是"它被拦了，然后改了什么"。这不需要新格、不改内核，只把已有的 `turns` + `read_back` 并排显示。

## 7. 要你圈的三个决定

1. **形态**：单文件本地开（最快、无依赖）／ 由 `kaudit` 的 `/` 吐出来（我倾向这个，但会动 `cmd/kaudit`，要加 1 根针）。
2. **原文显示**：默认不显示、需一次点击（我倾向这个）／ 干脆永不显示（那就做不成了④对质台之外的解释能力，但更安全）。
3. **端口与暴露**：只绑 127.0.0.1（我默认走这条）／ 要给别人看就得绑网段 + `KAUDIT_TOKEN`，那台机器现在还叠着云侧安全组那一层未知（见 `报告/防火墙检查-1015.txt`）。
