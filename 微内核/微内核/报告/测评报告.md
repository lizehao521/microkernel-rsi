## 2. 结论

- **作为阶段一交付物：合格，偏强。** 不变量清晰、每条都能被证伪（51 根针 0 空针）、隔离机械可核。

- **一句话：纪律是真纪律，证据是自证，消费方缺席。目前是一份写得很好的契约，还不是一个被用过的内核。**

## 3. 四条不变量（包自己声明的）

1. 每个数都带"谁算的"：`Basis` = measured / relayed / estimated / model_says / absent / unset，零值 unset 在门口拒收。
2. **缺席 ≠ 0 ≠ 忘了填**：三态量 `Measure`，缺席必须带理由。
3. 一格一量：`content_bytes` 与 `wire_bytes_out` 不许共用一个键名，撞名直接拒。
4. 一个定义一个 owner，**且 owner 要被复核**（重算一遍再比对，不许只写在注释里）。

外加两条工作方式上的要求：每个判据要**两侧**都验（坏的拒 + 好的收）、每个判据要**能看着它红**。

## 4. 外部对照：考题 android-bench

用它当尺子量内核（不是拿它跑分）。它跑不了本机，三条硬证据：
`utils/docker/prebuild.py:37-40` 认出 Windows 直接 `sys.exit` **[核]**；`harness/evaluation/benchmark_worker.py:104` 无条件 `devices=["/dev/kvm"], privileged=True` **[核]**；README 称每类镜像 +40 GB，本机 C 盘剩 14 GB **[核]**。

### 4.1 真实生产代码里确实存在内核拦的那几种形状

| 形状 | 考题实况 | 出处 |
|---|---|---|
| 忘了填 == 真零 | 整份 trajectory 解析失败只 `logger.warning`，字段留在默认 0 / 0.0（`benchmark.py:305-308`） | [核] |
| 明知分不出仍挑一个填 | `harness.py:466-469` 注释原文："cannot differentiate between BUILD_FAILED and TEST_FAILED in this case / so marking it as TEST_FAILED" | [核] |
| 默认值即判定 | 跑之前先把每题预填 `AGENT_NO_PATCH`（`harness/evaluation/main.py:220-223`） | [核] |
| 缺席与 0 混 | `cost` 缺省 `"$0.0"` | [转] |
| 一格两量 | 键 `steps` 一路是 litellm `api_calls`、一路是分组 message 对 | [转] |
| 写了没人读 / 读了没写 | HTML 工具读 `trajectory_path` 而产出方从不写它；`COMBINED_RESULTS_FILE` 只读不写 | [转] |
| 文档与代码不一致 | 文档教读 `EVAL_ERROR` / `NO_PATCH_GENERATED` / `SKIPPED`，这三个词在所有 `.py` 里 **0 命中** | [核] |

**这一节的意义**：内核那三条"洁癖"不是我为难自己，是别人在生产级基准代码里天天犯的形状。方向有据。

### 4.2 考题做对了、内核没有的（真缺口）

1. **归因轴**：`Status` 分 `AGENT_*`（模型的锅）与 `INFRA_FAILURE_*`（环境的锅）两套命名空间（`benchmark.py:63,71`）[转]。内核只有 `FailKind` 六值 + `RetrySame()`，**没有"这一发的失败算谁的"这一格**。
2. **多跑聚合**：测试重跑 3 次、`--num_runs`、pass@1 + bootstrap CI + 题目/轮次方差分解、稳定性分 `S=(P−F)/n`（均值 0.85）[转]。内核是一发一账，同题多发没有聚合语义。
3. **分数不背环境的锅**：`benchmark_worker.py:173/187/201/217` 四处 infra 失败一律写 `score=0.0` [核]——归因写在元数据里，判决却没读它。内核干脆没有 score 格：这是对的（分数不是元数据），但也意味着它不阻止你把一个 0 当判定记进账。

### 4.3 内核是超集、却没有外尺可照的部分

考题全仓**零个**字节字段，也没有 chunks / 首字节时延 / 块间隔（只有 `total_latency_seconds` 一发总时长）[转]。所以内核的 `content_bytes` / `wire_bytes_out` / `wire_bytes_in` / `chunks` / `first_byte_ms` / `max_gap_ms` 这几格，**目前只有自己的 51 根针在自证，没有任何外部实现验证过**。这是最薄的一环——不是缺陷，是未被外部证伪。

## 5. 内核自己的四条问题

1. **没有消费者。** `runloop` 全仓没有一行 `import agentkernel` **[核]**。快闸里"RecordCall 整发落账：链上 47 条"用的是闸门自搭的样例 **[核]**。契约层的正确性目前只由自造输入证明，而自造输入正是最容易自欺的地方。
2. **没有落盘。** 非测试、非 cmd 代码里 `os.Open` / `os.WriteFile` / `ioutil` **0 命中** **[核]**——账本活在内存里，而它全部的卖点是事后可追溯。叫微内核，但没有持久层，也没有读端的真实使用者。
3. **判据成本随格子线性涨，收益不涨。** `clamp_rounds` / `notice_why` / `leftover_pct` 这类格破了不影响任何决策，却各自要养针。慢闸已 51 根、要跑几分钟；包还没有真实调用方来证明哪些格值这个价。
4. **枚举完备性是单样本假设。** 六档 Basis、六值 FailKind、四值 Squeeze 全部从 runloop 一份代码提炼。考题里那个归因轴它就没有（4.2 第 1 条）。"字段表收全了"是未验证的推断。
