几何-出处页六档-1025 · agentd 轨迹页（trace.html）横向溢出实测
=====================================================================
这一份只回答一句话：手机宽的视口下，agentd 那张轨迹页还横着溢不溢出。
结论在最后一节；中间每个数都是本趟（2026-10-25 13:1x–13:2x）同一把尺子现量的。

一、跑法（两页同一把尺子、同一趟浏览器会话）
---------------------------------------------------------------------
  尺子：报告/几何-出处页六档-1025-尺子.html.txt
        原件 = Temp/ak1025-d2/harness3.html，sha256 6b03c4925d56c30d…，两件逐字节同
  服务：python -m http.server <随机空闲口> --bind 127.0.0.1，cwd = Temp/ak1025-d2（两页同源）
  页面 A「改前」：web/trace.html   sha256 2554898cde0d590c…  111,299 B（08:18 生成，早于 trace.go 的修改）
  页面 B「改后」：web2/trace.html  sha256 fa9f305bd41bc92c…  111,604 B（13:12 由修后 trace.go 重出）
    生成命令：go run ./cmd/agentd -driver scripted -script happy -max-turns 6
              -journal-out …/账3.jsonl -events-out …/账3.events.jsonl -trace-out …/web2/trace.html
    go run 的退出码是 1（正文 exit status 3 =「轮次额度到」），与改前那一趟同一形状。
  视口：被测页装进 px 宽的 iframe（七档 1440/1100/900/700/528/390/320），iframe 内文档即真实 CSS 视口。
  两态：
    closed = 页面原样 —— 6 个 <details> 默认关着；
    open   = 把 6 个 details 全展开再量 —— 每一发的侧表这时才进排版。
    为什么非分不可：关着的 details 子元素仍能报出 getBoundingClientRect，但不参与祖先的
    scrollWidth（本趟实测：关着的 details 里那张 2000px 宽的表一个像素也没撑宽 documentElement）。
    第一版尺子只量一态、又按 rect 挑「最宽的表」，于是把 12 张没排版的侧表读成了撑宽者 ——
    这一版把这条错路写在这里，免得下一手再走一遍。
  overflow_px = max(documentElement.scrollWidth, body.scrollWidth) - documentElement.clientWidth

四、臂：只证尺子有牙，不算产品读数
---------------------------------------------------------------------
  做法：390 宽、details 全开、把在流里最宽那张表 style.minWidth 改成 2000px，重量。
    改前页：整页溢出 386 → 1637 px      ⇒「页面级横向溢出」这把尺子量得到
    改后页：整页溢出 0 → 0（壳兜住了），壳内最大可滚 397 → 1649 px
             ⇒「壳能滚」不是算出来的空话；同时它说明压成 0 靠的是滚动容器，不是裁切
  第一版尺子在改前页上做过一根「空臂」：minWidth 打中的是一张关在 details 里的表，
  整页溢出 238 → 238 一动不动。那根臂被这版丢掉了 —— 臂打不中，不是「尺子没牙」，是「臂接错了地方」。

五、与 08:20 那一趟的对账
---------------------------------------------------------------------
  08:20 读数（Temp/ak1025-d2/几何六档.json）：528/390/320 = 91/229/299，撑宽者 TABLE.@604，arm 1637。
  本趟量同一页（sha 2554898c…）＝ 100/238/308，撑宽者 TABLE@613。
  三档都差常数 +9 px —— 两把尺子的视口口径不同（那趟按外窗口取视口，本趟按 iframe 的
  documentElement.clientWidth），不是页面变了（改前页字节自 08:18 起没动过，sha 可核）。
  形状、撑宽者、量级一致 ⇒ 互相当作复现；两个数不并成一个，也不拿 +9 去反推谁的页面更宽。

七、结论与边界
---------------------------------------------------------------------
  结论：改后页在七档（1440…320）两态下，页面级横向溢出全部是 0；窄档里比视口宽的表
        都装在 computed overflow-x:auto 的壳里，壳真有可滚宽度（15…311 px），臂把它撑到 1649 px
        时页面仍 0 溢出。改前页在同尺下 528/390/320 关态 100/238/308、开态 248/386/456。
  这些绿不说什么：
    - 结构针（TestEveryTraceTableScrollsInsideWrapper）的绿 ≠ 几何已达标：它只数「13 张表装在 13 个壳里、
      样式串里有 overflow-x:auto」。壳真能滚、页面真不溢，只有本文件这一趟的数说得了。
    - 量的是「页面横向不溢出」，不是「手机上好看」：td 最小字号 12 px 在七档都成立，其余可读性没量。
    - 窄屏截图不算几何证据（headless 画布可能比 CSS 视口窄，右边被裁）；本趟只留 1440 那张图肉眼核。
    - 浏览器是 Qoder 内置浏览器（Chromium），不是真手机；真机 NOT_RUN。
    - agentd 页面之外还有哪些页面横溢，本趟没量（不适用 ≠ 挡住了）。
