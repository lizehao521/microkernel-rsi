一 · #65 `Basis` 的值域不校验：契约只有 0..5，`Basis=9` 整发放行

读数（逐名只改一处，其余全同）：
- A `wire_bytes_in = {N:4096, Basis:1(measured), Source:""}` → **放行**。
  这半句要说清：**放行是对的**，不是漏。`contract.md` 键名表把 `call / parts / content_bytes / call_bytes_ceiling / notice_sent / streaming / finish_said` 等格的
  Basis 直接定为 measured，出处那一列填的是 **owner**（框架·装配器／人·配置／内核·公式／框架·裁剪器／框架·调用器），不是 `Source` 文本。
- B `Basis:3(estimated) + Source 空` → **拒**：`kernel: 通道上收到的字节 说是 estimated 的，却没说来源（转述谁 / 估的是什么）`，且原始 `isError=true`。
- D `Basis:2(relayed) + Source 空` → **拒**，同一模板换词，`isError=true`。
  ⇒ **「规矩①在预检上没有 enforcing 分支」这句被证伪**（这是上一个会话的结论，我复现时推翻的；它以为没分支，是因为它交的谎账用的是 `Basis=1`）。
- C `Basis:9（契约 0..5 之外）+ Source 有值` → **放行**。
- 代码面：全仓搜不到任何 `Basis` 值域校验（`kernel.go:234` 那处 `for k := range t.ByBasis` 是遍历计数桶，不是校验）。

能说什么：**今天实测到的只有"值域外的码被预检放行"这一条**。
**不能说什么**：它落账之后 `tally` 会不会把它单列一桶、还是渲染成空名字——**我没测，也不打算测**（要测就得把 9 真落进账）。
所以这条的后果那一半目前是**推断**，写件里就是为了不让人把它读成已知的严重度。

三个选项（各带代价）：
① **加一条值域判据**：`Check()` 里对 `Basis` 取值范围硬拒，文案沿用现有模板族。

   「只被 1 条碰过的格」那个数会变（4 → 未知）；整轮凭据再过期一次（基线要到 `1017an`）。
② **只在渲染处归一**：值域外的码一律显式渲染成 `非法码(9)`，不拒。代价最小，但"没拒"这件事仍然在。
③ **明写不校验 + 写进 §8 缺口清单**：承认外壳不校验调用方交来的码，把它归到"调用方诚信"那一族。

二 · #66 `Cuts` 的「整块没给」与「给了空表」在链上不可分辨

读数：
- E1 `input` 里把 `Cuts` 整块删掉、E2 显式给 `Cuts: []` → 两发 `check_call` 回话**逐字相同**（各 55 字，都是 `整发可落账`）。
- 再看这个进程里**已经落过的两发**（第 1 发省 `Cuts`、第 2 发给空表，`session=mount-check`）：
  读回来的 `clipped / dropped / folded` 三格**逐字相同**，都是 `measured 0 段（裁剪表是空的）`，缺席栏都是 `[]`。
- 工具描述自己写着：**「没给与给了零值是两件事，外壳不替你补一份『量到了』的账」**。
  ⇒ 这句话在 `Notice / Finish / Failure` 三块上**生效**（整块不给会被门拒），在 `Cuts` 这一族上**不生效**。

这是口径与文案对不上，不是数错：要么把 description 那句收窄成"仅限三个整块"，要么给 `Cuts` 一个"没给"的第三种状态。
选项：
① 收窄文案（改 description 一句，代码不动）⇒ 代价最小，但"没给"与"空表"仍然同格同值，读账的人分不清当时有没有裁剪器；
② 给 `Cuts` 加"整块没给"的显式状态（`Cuts` 三格记 absent 而不是 measured 0）⇒ 这**动的是判据表口径**，按 §8 与 48 键/49 格那条规矩要三件配齐，
   而且会让已封板那一版的读数与新版的读数**不可比**（今天这两发就是例子）；
③ 记成已知缺口写进 §8，不改。
