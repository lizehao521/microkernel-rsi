# 改动单 · 闸门事件计数（2026-10-18 夜 · 作者批准"俩个都改"）

## 要解决什么

产品唯一 KPI 是「闸门今天拦了几次、拦在哪一格」。这句话现在**两处兑现不了**：

1. **预检那一路一个数都不记。** `mcpsrv.go:332-341` 的 `kernel.check_call` 有三个拒收出口
   （门口整块没给、参数解不开、内核判据不自洽），三条**都不进任何计数器**；
   四个桶只统计写请求（`record_call` 那一路）。⇒ 外部调用方被拦 24+ 次，账上四栏全 0。
2. **计数活不过落盘。** `kernel.go:120` 的 `countRejected` 只在内存里加；
   `journal.go` 编出来的字节里**没有它的位置**，`LoadLedger`（journal.go:331）也就无从恢复。
   ⇒ 只读审计面 `cmd/kaudit/main.go:159` 对任何文件账本都报 `rejected_writes = 0`——
   把"没记过"念成了"没拦过"，正是这一包第一不变量反对的形状。

**这不是缺一只计数器，是缺一个带出处的格位形状**：一个数在"落盘后不可知"与"量到了 0"之间必须分得开。

## 动哪几处（都在账本事件层，不碰判据表）

| 处 | 动法 |
|---|---|
| `kernel.go:117-121` `Ledger` | 加 `countPrecheck`（内核判据在预检里拒的整发数）与 `countPrecheckDoor`（外壳门口挡下的预检请求数）；再加一位 `countersKnown bool`：内存里加过就是 true，从盘上读回来带 gate 行也是 true，**没有 gate 行 = 不可知** |
| `kernel.go:228-229` | 补三个访问器：`PrecheckRejected()`、`PrecheckDoor()`、`CountersKnown()`；`NotePrecheck*` 由外壳调（内核自己数不了预检，它不参与预检） |
| `journal.go` `MarshalJournal` | 末尾追加**一行非链上的** `{"gate":{...}}`：七个数 + 一个 `known:true`。它不进 `Docs`、不参与 `seal`、不改任何 `seq` ⇒ **`verify` 的条数一个字不变** |
| `journal.go` `ReadJournal` | 单独识别 gate 行，计进 `Journal.GateLines`（**不许进 BadLines**，否则"闸门那一栏"会被念成"有一行坏了"） |
| `journal.go` `LoadLedger` | 有 gate 行 ⇒ 恢复计数并置 `countersKnown=true`；没有 ⇒ 保持 false，读数一律走"不可知"这句话 |
| `mcpsrv.go:332-341` `check_call` | 三个出口分别计数：内核判据拒的 → `countPrecheck`；门口/解不开 → `countPrecheckDoor`。与落账那两栏同一条纪律：**永不相加**（#42/#46 的教训就是"谁拒的"一合就答不出） |
| `mcpsrv.go:368-378` `tally` | 四笔数扩成六笔 + 一句"这几笔从哪儿来的"（内存现数 / 从文件恢复 / 不可知） |
| `cmd/kaudit/main.go:159` | `rejected_writes` 在 `countersKnown=false` 时**不许报 0**，报不可知 |

**不动的**：49 格 / 48 键那张判据表、§8 十五条、`Basis` 值域、`Failure.Kind` 枚举。
**不做的**：不把拒收落成链上条目（那会把 `RecordCall` 的"写入被拒"语义污染掉，还让 append-only 的分母变成两本账 —— 外部调用方的 S1 里同一条"不做什么"，我照收）。

## 证红（改动生效后必须亮的那一下）

- 连做 10 次故意错的 `check_call`（内核判据层）→ `tally` 那一栏报 **10**；改前报 0。
- 落盘 → 重开进程 → `load_journal` → `tally` 仍报 10（改前：报 0，且这 0 长得像"量到的"）。

## 反臂（改动**不该**亮的场合，缺一不合）

1. 10 次**全过**预检 → 那一栏必须是 **0**（不许把"检查过 10 次"念成"拒了 10 次"）。
2. 用**没有 gate 行**的老账本（现成的两份：8797 的 2940 条导出件、8799 的 490 条快照）读回来 →
   必须报**不可知**，报 0 就是这次改动自己要拦的那类错。
3. 加了 gate 行以后 → `verify` 的条数与指纹必须与加之前逐字相同（链不许被计数动过）。
4. `check_call` 通过时 → `rejected`/`precheck_*` 三栏都不许动。

## 代价（写在批之前）

- 账本格式加了一行 ⇒ 第三方按"一行一条记录"扫文件的旧读者要把 gate 行认出来（我会写进 `contract.md`）。
- 六笔数比四笔更难读；但"拦了几次"是唯一 KPI，读不动它就没有 KPI。
- 改完要重跑 `打包.py`（二进制变了），zip 哈希作废旧的。
