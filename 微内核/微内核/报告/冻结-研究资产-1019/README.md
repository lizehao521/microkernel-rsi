# 研究资产 C：可验证记账层

**冻结日：2026-10-19 ｜ 状态：研究资产，不是已验收产品 ｜ 重开条件见 §5**

---

## 1. 这是什么

一套研究“Agent 的说法能不能被复核”的记账内核包，包含：

- **源码与契约**：一次调用 49 格、48 个唯一键名（输入侧 20 格、输出侧 29 格），每格是“值 + 档位 + 出处”；任一格不自洽，整发拒收；账本用哈希链串起来。
- **三把尺子**：
  - 封板轮整轮（键名表、格数、漂移）；
  - 80 根慢闸整轮（空针 / 坏针、独立复算）；
  - 双臂验收探针（干净臂、坏臂、对照臂、反针）。
- **证据与失败档案**：已硬证 8 条、未成立或未证 10 条；缺口目录 12 条；外部评估原文与对账。
- **一份对外白皮书草稿**：`报告/发布-1019/白皮书-当Agent说我做完了-1019.md`，以及它的机械自检。

它研究的核心问题不是“Agent 能不能干活”，而是：**一次任务结束后，我们能不能说清每一句结论的值、档位和出处，并且不把“没量到”写成 0。**

## 4. 怎么复核

### 4.1 复核白皮书的数字出处（零成本，不启动内核）

```text
C:\Users\Admin\sdk\py314\python.exe 报告\发布-1019\发布前自检.py
```

期望：`判定：PASS ｜ rc=0`；并且打印“合成红样本会红、干净样本会绿”。如果它显示 PASS 但红样本没红，说明尺子坏了，不能采信。

### 4.2 复核双臂脚本读数（会启动一个临时内核）

按 `报告/双臂验收决策件-1019.md` §8 的步骤：从当前源码构建临时 exe，选空闲端口，核 owner / 监听 pid / bind 错误，再跑 `报告/双臂验收-探针-1019.py`。

只认四行同时出现：

```text
弱判据=PASS
严格判据=FAIL（当前状态；重开后要求 PASS）
B1 点名形状=WEAK（当前状态；路径 A 后应为 STRICT+LABEL）
B2 点名形状=STRICT+LABEL
```

如果 exe sha256 不是 `f6061740…`，读数不能与本包逐行比对，只能当新一程。

### 4.3 复核“严格判据为什么 FAIL”

读 `报告/双臂验收决策件-1019.md` §4.2 与 §4.4；再读 `cells.go` 的 `Readers.Declare`（只返回错误，不碰计数）与 `mcpsrv/mcpsrv.go` 的 `declare_reader` 分支（返回文本，不碰六桶）。这两处是“第五类拒收没有桶”的代码位置。

## 5. 重开条件（两条都做到才重跑）

1. **事件层**：给 `declare_reader` 的拒收补一个 `reader_refused` 桶（或等价的、能区分“整发拒收”与“声明拒收”的计数），带 GateState，并进契约与 80 根针。
2. **人工**：找一个没参与过项目的人在 30 分钟内跑通干净臂，留下链验证与逐格读数。

两条都做到后，重跑双臂探针，要求弱判据与严格判据同时 PASS，才可以把状态改成“双臂已通过”。

如果作者明确接受弱判据，并把坏臂要求改写成“拒收必须在工具响应里可见，第五类拒收今天没有桶”，那么可以改判据；但必须在看板上留一条，不能悄悄降级。

## 7. 冻结纪律

- 本目录不改内核源码、不改判据格、不写 8797 / 8799 的真实账本。
- 冻结后若有新实验，开新的日期目录，不覆盖本目录的读数。
- 对外引用以主报告与白皮书为准；本 README 只作导航，不新增读数。
- 引用白皮书时，先跑 §4.1 的自检；引用双臂时，先核 §3 的 exe 哈希与四行判据。
- 不要把“脚本弱判据 PASS”写成“双臂已通过”；不要把“审计层”写成“防线”；不要把“没找到付款证据”写成任何市场结论（既不能写成“已被市场验证”，也不能写成全称否定）。

## 8. 一句话

**它能证明的是：每一格 Measure 的值带档位与出处，任一格不自洽可整发拒收，链可比对原像，80 根慢闸整轮跑过且对照臂会红。**
**它不能证明的是：它挡得住攻击、它让 Agent 做得更好、它已经通过双臂验收、它有市场。**
