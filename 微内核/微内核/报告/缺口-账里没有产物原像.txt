# 缺口：账里没有一个位置装"产物的原话"（三臂实测跑出来的，不是设想的）

日期：2026-10-16 00:0x · 来源：`tasks/mcp/artifact_probe.py` 三臂，读数原文 `报告/产物对质-三臂.txt`

## 三臂实际落在哪儿（判分线是跑之前写死的，见脚本头部）

| 臂 | 判分线 | 实测 | 结论 |
|---|---|---|---|
| A 把模型自述的 token 标成 `measured` | 必须 `isError` 且点名判据 | `isError=False`，但正文里**确实**说了：`kernel: token 那一格的出处是 measured —— 我们数不出对端的分词，只有估算或转述两种可能` | **未过**。两次复现，不是偶发 → 归 #20 |
| B 真运行的 stdout 落账 | 必须落账、`verify` 绿且比对过原像 | `整发落账 49 条 …` + `✓ 链自洽（共 49 条，其中 49 条比对过原像）` | **过**（题面 `print(0.1 + 0.2 == 0.3)`，真运行 `False`） |
| C 种坏（改 payload 留原指纹 / 连指纹一起改） | 两种都必须被拒 | `账里以真 stdout='False' 当 payload 的格数：0` | **测不了**——不是脚本坏，是账里**没有一格存着产物原话** |

## C 为什么测不了（这是本次唯一的新知识）

把 `报告/样例-toolface-1015.jsonl` 逐格解码看过的结果：**49 格每一格的 `payload_b64` 存的都是"那一格自己的值"**——

```
model_output:model_says_bytes     claim='2'    payload='2'
model_output:model_says_kept      claim='2'    payload='2'
model_output:model_says_sha256    claim='73475cb40a56…'  payload='"73475cb40a56…"'
```

也就是说：**产物（stdout 原文）从来没进过这本账，进来的只有它的长度和它的指纹。**
于是"第三方能不能重算原值"这句话对产物这一类**是反的**：
链能保证的是"这条记录没被改"（`payload ↔ PayloadH`、整格 seal），
而拿一串 sha 只能**正向核验**（你给我一个候选答案，我算 sha 看等不等），
**不能反向读回原话**——因为原话不在场。所以 C 臂那种"改内容留指纹"的坏法在这本账里没有落点。

## 三条路（我推荐第一条，第二条要破封板）

1. **链外放原像，链内放指纹，对质时双向核验**（不加格、不动内核）：调用方把 stdout 写进一个文件，
   账里存它的 sha；对质台（面板第④块 / `kaudit`）拿"文件 + 账"做交叉验证：文件被改 → sha 对不上；
   账被改 → 链当场 `✗`。代价：`文件在不在`这件事链管不着，且需要规定文件命名/寻址——这正好是
   调研里 [in-toto / SLSA provenance](https://github.com/yzhao062/awesome-auditable-ai) 已经在解的问题，可以直接借它的语义而不自己发明。
2. **加一格装产物**（例如 `says_text`，出处 `relayed`）：**这是加格，破 §8 的封板标记**，
   要走"先立实例、再立判据"——好消息是**实例今天已经有了**（就是这条 C 臂测不了），
   坏消息是它要重跑整轮 + 改 49→50 的所有引用。不轻，所以我把它排在方案 1 之后。
3. 只做 A 臂那个缺陷（把 `check_call` 的 `isError` 修对），产物这一侧先不碰——
   那等于承认"编程场景对质"这条线暂时不追。

## 一句话结论

**这一趟没能证明"内核是产物对质的裁决器"，但证明了它缺一副能对质的手铐**：
指纹在场、原话不在场。方案 1 今天就能做且不动判据表；方案 2 是加格，得你先点头破封板。
