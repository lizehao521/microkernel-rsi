### 硬缺陷 4

**H1 — GateState 不落盘，三态在「落盘→重开→读回」这一路被压平（P0 邻域，规矩一）**
- 位置：`journal.go:91-96`（`gateLine` 只有 Gate/ChainHead/Seal/Version，**没有状态位**）、
  `journal.go:502-507`（`LoadLedger` 对任何带 gate 行的账**无条件**置 `GateLive`）、
  `journal.go:127`（`MarshalJournalWithGate` 不看 Ledger 自身 `GateStatus` 照写 gate 行）。
- 为什么是缺陷：三态（Unknown/Live/Partial）只活在内存，字节里只有「有没有 gate 行」。于是——
  - **Unknown 被洗成「量到的 0 / 这一程完整可数」**：一本从老账本读回的 `Unknown` 账，`Gate()` 返回全 0；
    一旦再 `MarshalJournalWithGate(l1.Docs(),…)`（例如走 encode 那一路）就落出一行合法 gate，读回即 `Live`。
    运行时复现 `P1b`：`Unknown 账本导出再读回 → HasGate=true、状态=Live(1)、说法="这一程完整可数"`。
    这正是本次改动要杀的那个形状（缺口 #51：把「没记过」念成「没拦过的 0」），换了个入口复现。
  - **Partial（下界）被洗成 Live（全量）**：`P2b`：载入无 gate 文件→数到一笔→`Partial「只覆盖这一程」`→落盘→读回 = `Live(1)`。
    「载入前那一段无从知道」这句话连同它的下界语义，一次往返就没了。
- 与批准单不符：改动单第 21/25 行要求「再加一位 `countersKnown`」并把「七个数 + 一个 `known:true`」编进 gate 行；
  交付的 `Gate`(kernel.go:128-135) 六格无 Known、`gateLine` 无 state —— **`known` 那一位没落地**，
  而它恰是让三态跨过磁盘边界的唯一机制。
- 复现：`m2probe` P1b / P2b（go run，见第三节）。
- 修法：`gateLine` 增一个 `state`（或改动单原话的 `known`+是否 Partial 的一格）；`MarshalJournalWithGate` 由 Ledger 交出 `GateStatus`；
  `LoadLedger` 按落盘状态映射，**不再**见到 gate 行就 `Live`。
- 验收判据：P2b 读回须是 Partial（或新态），不得印「这一程完整可数」；
  P1b（Unknown→encode→load）须落在 Unknown/Partial 或点名不可信，**不得**给出「有 gate + Live + 拒落账 0」。

**H2 — 坏 gate 行被 GateLines 与 BadLines 双计 ⇒ `Journal.String` 假绿（规矩五 分母自印）**

  `journal.go:219` 的「计数栏：有」分支键在 `j.GateLines > 0`（不是 `HasGate`）。
- 后果（源码形态 + 运行时 `P3`/`P3c` 双证）：
  - 单坏 gate 行：`ReadJournal({"gate":"坏"})` → Lines=1 Parsed=0 GateLines=1 BadLines=1 HasGate=false，

    「扫了几行/解开几行」少报 1，同时尾句仍印「计数栏：有（0、0）」。

  所以假绿落在 **直接用 `ReadJournal`+`Journal.String` 的读者** 与 Journal 自带的分母字段本身（Lines/Parsed/GateLines/BadLines 互相不自洽）。
