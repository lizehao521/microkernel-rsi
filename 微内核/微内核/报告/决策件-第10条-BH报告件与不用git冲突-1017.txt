二 · 四个选项，各自的代价与"什么会变成绿/红"

① **就这样收：BH 的交付 = scan + plan 两件，canvas 报告件不出。**
   代价：对外看像"这一家只跑了个只读扫描"；BH 自己那套 readiness 维度分数与报告面（优先级动作、修复提示）缺失。

   不会得到什么：任何"读代码看不出、只有报告面能给出"的结论 —— 这一轮本来也没指望它。

② **授权 quick 深度**（它契约规定 quick 只能由明确点名触发，所以这条得你点头）：
   跑 `harness evidence-bundle --depth quick`（7 天窗 / 3 件资产），`projectHarness` 会**在报告里明标 unavailable**，
   然后我按它的 Step 2–4 走三道独立证据道（会话那道会是 0 输入）→ `harness render --validate` 出 `report.canvas.tsx`。
   会得到：一份真报告件 + findings.json。
   代价与要说破的：报告只覆盖 3 道里的 2 道、窗口只有 7 天、置信度被它自己降为低；
   那份件**不能**读成"BH 认证过这个仓库"，只能读成"BH 在缺一道输入的情况下给的低置信度读数"。

③ **允许建「替身树」跑一次（明标替身、不算验收）**：
   在 TEMP 里把 `.go`/`go.mod` 拷一份成一次性 git 工作树（一个 commit 即可），拿它当 `--workspace` 喂 BH ⇒ `projectHarness` 那道真能跑。
   代价：报告描述的是**那份拷贝的伪历史**（一个 commit，没有真实变更轨迹），所以它对本仓库的"变更置信/核心改动_watch"一类结论全是造的；
   必须像 E 段那三个替身一样，在件上写死「替身、不是本仓库的历史、不算 BH 对本仓库的结论」。
   你的仓库本身仍然不 `git init`，回滚仍走快照点。

④ **把本仓库变成 git 工作树**（正面推翻"不用 git"那条）：
   这是唯一能让 BH 各道都"名正言顺"的修法，也是我不替你做的：它动的是回滚路径本身
