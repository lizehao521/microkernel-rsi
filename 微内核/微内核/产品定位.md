# 产品定位（v1 封板用）

日期：2026-10-13 · 状态：**已按这一定位封板**（用户 2026-10-13 夜以「设置目标进行」定下这轮目标；
五个待定口径同日全部落进判据表，§8 已挂「15 条为止停止新增」的封板标记，判据表冻结在 48 键 / 49 格）。
凭据与逐条对照在 `报告/封板报告-v1.md`；76 根针的整轮慢闸已在修好夹具之后重跑并全绿

## 一句话

**给 Agent 的每一句话上税：说不出"谁算的"，就进不了下游。**
交付形态是一个能挂进任何 Agent 框架的证据闸门（MCP 服务 + 一本可验链的往来账），
不是一个 SDK、不是一个评测榜单、不是模型。

**这一句在 10-15 被外人量到过一次，读法要修**：一场 8 题盲测里，纯模型 8/8、带这颗内核 6/8，
唯一一次工具调用是只读侦察（`kernel.celltable`，回的 49 格/48 键与预期一致）。
测文自己的根因写得对——**内核管的是"报账的出身与自洽"，不跑代码、不判语义**，
所以那批题的对质物（JS 输出、语言事实）**不在它的能力域里**。
结论：**它是追责/拦编数层，不是答题增益层**。谁按"能力增强"来理解第一句话，谁就会拿答题考它。
能推翻这条判断的只有一件事：**产物对质**——真运行的 stdout 落进账里当 `measured`，
自述冒充它时必须被链当场拒（三臂跑法已写成 `tasks/mcp/artifact_probe.py`，判分线写在跑之前）。

## 边界三条（对外要写在最前面 · 2026-10-18 由作者定死，限定词是「运行时」）

**内核是「记账件」，不是工头 —— 运行时不调度、不联网、不执行工具。**

| 运行时不做 | 准确含义 | 代码实测（10-18 现查） |
|---|---|---|
| **不调度** | 没有循环、没有定时器、不决定"下一步做什么"。谁调它、什么时候调、调完去干什么，全是调用方的事。 | `time.Ticker` / `time.AfterFunc` / cron / schedule **0 处** |
| **不联网** | 不主动外呼：不调模型、不取任何外部数据、不推送。 | `http.Get` / `http.Post` / `http.Client` / `net.Dial` / `url.Parse` **0 处** |
| **不执行工具** | 不跑命令、不加载代码、不碰执行位。它只按判据决定**一笔账收还是拒**。 | 运行时路径 **0 处**；唯一 `exec` 在构建期自检，见下表 |

**两处必须一起说，否则会被反问**：

| 例外 | 是什么 | 为什么不算破边界 |
|---|---|---|
| 被动监听回环端口（`mcphttp`） | 等人来记账的入口；非本机监听才要口令 | 是 inbound 服务，不是外呼；它自己不主动连任何机器 |
| 读写账本文件（`encode_journal` / `load_journal`） | 落盘与把账供出去 | 是记账的一部分，不取外部数据 |
| **`isolate.go:336` 会 `exec.Command(go, "list", "-deps", "./...")`** | **构建期自检**：证明自己的依赖集仍是纯 stdlib | 它 exec 的正是 `isolate.go:28` 那条注释给 `plugin.Open`/`os/exec` 立的隔离墙——**它跑的是禁止别人走的路，不在运行时路径上** |

一句话版本：**运行时它只把"这个数从哪来"记成档、事后赖不掉；调度、联网、执行工具都是调用方的事，构建期那个自检是唯一会跑外部命令的地方。**

## 买家与痛点

不是模型使用者，是**搭多代理流程的工程团队**。他们真正的事故是这两种，都不是"模型不够聪明"：

1. **说法漂白**：上游一个没依据的计数，被下游当证据写进结论。（本仓库 `kernel.go` 头部写的第 1 条不变量就是这个，来源是一次真事故。）
2. **出事之后拿不出发生过什么**：日志是人写的散文，改一行没人知道；问"这一发到底有没有被拒过"，答不出。

我们的答案有实测支撑，不是形容词：**一个 session 内核当面拒了 4 次不实装配**（把空响应记成正常收尾、
把类别谎报去留状态码、把对端自报的数标成自己量的、宣称通知发了而段里没有），
每一次都能从账上读出「被拒的写入 N 次」这个数并指名是哪一格拦的。通用 lint / eval 做不到这件事。

## v1 做什么（只这些）

- **输出闸门**：一发往来的 49 格逐格带出处，任一格不自洽 ⇒ **整发拒收、两侧都不写、拒收另计一格**。
- **可验的账**：哈希链，三态结论（自洽 / 不符 / **核不了**）——缺尾不许读成自洽。
- **一个能被机器读出的数**：闸门拦了几次、拦在哪一格、拒的是哪一路（落账 / 预检 / 门口 / 协议层 / 传输层）。
  这是产品的**唯一 KPI**。**10-18 起它才真的兑现**：原先预检那一路一个数都不记，而已记的数活不过落盘
  （`kaudit` 对任何文件账本都印 `rejected_writes=0`）—— 两个互不相知的外部调用方各撞过一次
  （`报告/外部评估-主页圈-aec6dd94-对账-1018.md`）。现在的形状与它仍答不出的部分写在
  `contract.md` 2.3b 与已知空洞第 4 条：**没有计数那一行 = 不可知，不是 0**。
- **接入成本**：起一个进程、发 10 个工具里任意几个、不改调用方的模型代码。**≤30 分钟接上，是验收项不是卖点。**
  成本的正确单位是**调用次数**而不是分钟：外人实测一圈 130 次里约 110 次花在记账与探型上，
  而"干活不记账、收口只落 1 发"那一发只用 6 次（`报告/外部评估-主页圈-aec6dd94-原文-1018.md`）。

## v1 明确不做（每条都有实测理由，不是"以后再说"）

| 不做 | 为什么，实测在哪 |
|---|---|
| 续跑记忆 / 供出历史 | 账上只有数与指纹，没有原文；新进程实测**能定 4 类计数决定、定不了 5 类内容决定**，一发真调用模型自己回「我不知道」（`报告/agent-第二支-续跑臂.md`） |
| 跨发一致性核对 | 唯一非人造路径（预算挤尾）跑出来了，但三把指纹**单位不同**，连不回原话；真实故障实例 **0 次**（`报告/挤历史-判生死.md`） |
| 训练数据集 | 完整的"犯错→裁决→改正"对只有 **2/4**，其余半边不存在（`tasks/audit/to_dataset.py` 实测） |
| 指令通道 / 主动改写模型输入 | 回边今天接的是装饰（`from_ledger=4` 自证）；先把闸门做稳，再谈它开口说话 |
| 并发多写 | `Ledger` 无锁、单请求串行是现状，写进文档而不是偷偷改成共享 |

## 唯一验收（可证伪，一条）

拿一个**不是我写的** Agent（新调用方，没背过任何判据）接上闸门跑一件事：

1. 账上 `被拒的写入 ≥ 1`，且每一次都能指名是哪一格拦的、内核原话是什么；
2. 全程链自洽、`sk-` 0 次、任何一格都不许出现"没量到却写成 0"；
3. 接入耗时 ≤30 分钟，调用方模型代码零改动。

**这一条已经在路上了**：`tasks/mcp/agent.py` 第一次交账就被拦（usage 标错档），
它是我们自己写的第二个调用方 —— 严格说还不算"不是我写的"。v1 的验收要找一个真没参与过这个项目的人接。

## 主要取舍（说在白纸上）

按这个定位走，等于**放弃"警卫员"那个更大的愿景里现在做不到的部分** ——
不主动改模型输入、不管跨发改写、不产训练数据。换来的是一个能在 30 分钟被别人接上、
且能用一个数字证明自己在拦东西的东西。**"能用一个数字证明"这句到 10-18 才名副其实**（见上面唯一 KPI 那条）。

**还有一处取舍必须写在白纸上：内核只做"拒 + 给原因"这一半，"改正"那一半不是它做的，也不全是产品带的。**
外面看到的闭环（被拦 → 拿到点名某一格的拒因 → 改对 → 落账）成立的前提是**调用方读过判据**：
`contract.md`、键名表、缺席写法、`Source` 那一格要填什么 —— 这些今天住在**我们写的文档**里。
所以对外不能讲成"接上就自动变严谨"：接上一个没读过判据的 Agent，它照样能被拒，
但拒因里那些键名与写法它无从下手。外人实测为此付的价是 130 次里约 23 次纯粹在学 contract
（`报告/外部评估-主页圈-aec6dd94-原文-1018.md`），这一笔是**接入成本**，不是内核的功劳也不是内核的过错，
是文档的账。要把这一半做成产品的一部分，做的是**教程与样例调用方**，不是再加一格判据。
反过来说：如果 v1 的验收找不到第二个人接上，那这个产品的真买家可能就不存在，
届时该改的是定位，不是再加一格。
